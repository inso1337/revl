# revl 2.0 — full language

You are writing **revl** source code. revl is a research language where systems
are built from components with *revertible effects*: every mutation carries an
inverse, and the runtime can unload or hot-swap any component by running the
inverses in LIFO order. revl 2.0 adds a TypeScript-subset layer of pure
functions and types around that core.

**Governing principle:** where a construct means exactly what it means in
TypeScript, revl uses TypeScript syntax verbatim. Where the paradigm's
semantics begin (effects, inverses, provisions), the syntax is distinctly
revl.

## Stratum 1 — pure functions (TypeScript subset)

```revl
pub fn score(items: List[Row]) -> Int {
  var n = 0
  for (r of items) {
    if (r.active) n += 1
  }
  return n
}

fn classify(n: Int) -> Str {
  if (n < 0) return "negative"
  return n == 0 ? "zero" : "positive"
}
```

- `fn` bodies are pure: no services, no effects, no host access.
- `pub` exports a declaration; unmarked is module-private.
- Admitted TS syntax, verbatim: number/string/bool literals, `[a, b]` lists,
  `{ id: 1 }` records, template strings `` `hi ${name}` ``, operators
  `+ - * / %`, comparisons, `&& || !`, ternary `c ? a : b`, arrow lambdas
  `x => expr`, method calls, indexing `xs[i]`, destructuring
  `let { id } = row` / `let [h, ...t] = xs`.
- `let` is single-assignment. Function-local mutation uses `var`, `while`,
  `for (x of xs)`, and compound assignment on `var` (`i += 1`).
- `==`/`===` (and `!=`/`!==`) both mean structural value equality.
- **Excluded** (compile errors): `class`, `new`, `this`, `function`,
  `import`/`export`, `typeof`, `try/catch`, `++`/`--`, generators.
- Plain double-quoted strings do **not** interpolate — never write `"$name"`;
  use backtick templates.

### Built-in methods (the stdlib surface — nothing else exists)

| method | on | semantics |
|---|---|---|
| `length()` | Str, List | element count |
| `push(v)` | List | **persistent** append — returns a new list; rebind: `out = out.push(v)` |
| `slice(a, b)` | Str, List | half-open sub-range |
| `charAt(i)` | Str | 1-char string |
| `charCodeAt(i)` | Str | code point at i |
| `indexOf(v)` | Str, List | first index, `-1` if absent |
| `concat(y)` | Str, List | joined copy |

Calling any other method on a plain value is a compile error. Values are
never mutated in place.

type Row = { id: Int, name: Str, active: Bool }

Built-ins: `Str, Int, Float, Bool, Unit`, `List[T]`, `Opt[T]`. `match` is the

## Stratum 3 — services and components (the paradigm core)

```revl
service Database {
  fn query(sql: Str) -> List[Row]
  emission fn execute(sql: Str) -> Int
}

component UserCache requires db: Database provides cache: Cache {
  config { ttl: Int = 300 }

  let store = effect Map.new() undo store.drop()

  await Job.run("warmup")

  provide cache {
    fn get(key) = store.get(key)
    fn put(key, value) {
      effect store.insert(key, value)
      undo   store.remove(key)
      emit db.execute(`INSERT INTO cache_log VALUES (${key})`)
           compensate db.execute(`DELETE FROM cache_log WHERE k = ${key}`)
    }
  }
}
```

- `service Name { fn ... / emission fn ... }` declares an interface.
  `emission fn` marks an irreversible operation; callers must `emit` it.
  A declaration is an **upper bound on its providers**: a plain `fn` may not be
  implemented by a body that reaches an emission — an `emit`, an `emission`
  extern, or a `fn` that transitively reaches one. An operation that is meant
  to emit must be declared `emission fn` in the service.
- Component header: `component Name requires a: A provides b: B { ... }`.
- Body statements: `config { name: Type = default, ... }` (read as
  `config.field`); named acquisition `let x = effect EXPR undo EXPR`;
  anonymous `effect EXPR undo EXPR`; `emit svc.op(args)` with optional
  `compensate svc.op(args)`; boundary `await Job.run(arg)`; and
  `provide name { fn op(p) = expr | fn op(p) { ... } }`.
- A call made only for its effect still needs a binding: write
  `let _ = kv.put(k, v)`, not a bare `kv.put(k, v)` — a plain call is not a
  statement.
- **Functions compose with components**: any expression position in a
  component (effect args, undo args, provide-method bodies, emissions) may
  call your `fn` declarations.
- Block effect form for multi-step acquisitions:
  `let conn = effect { let url = normalize(config.url) Pool.open(url, 4) } undo conn.close()`
  — last expression is the acquired value.
- Host constructors (stub objects for `effect` expressions):
  `Pool.open(url, size)`/`.close()`/`.query(s)`/`.execute(s)`,
  `Map.new()`/`.get(k)`/`.insert(k, v)`/`.remove(k)`/`.drop()`,
  `Job.run(x)` (only under `await`). Host objects keep their own methods —
  the stdlib table does not apply to them.

## The rules the compiler enforces (guarantees)

- **G1**: a component may only touch services bound in its own `requires`.
- **G4**: every acquisition carries `undo`; irreversible operations are
  `emission fn` and are called with `emit` (+ optional `compensate`).
  Irreversibility propagates outward: a `provide` method that reaches an
  emission is legal only where the service declared that operation
  `emission fn`.
- `undo` is a single call — it cannot register new effects.
- `fn` bodies cannot reach services or effects (G6, by construction).
- `provide` blocks implement exactly the service's operations; no duplicate
  providers per service (G2); requirement graphs are acyclic (G3).
