# revl — component-composition language (1.x surface)

You are writing **revl** source code. revl is a research language where systems
are built from components with *revertible effects*: every mutation carries an
inverse, and the runtime can unload or hot-swap any component by running the
inverses in LIFO order.

## File shape

A `.rvl` file is a sequence of `service` and `component` declarations.

```revl
service Database {
  fn query(sql: Str) -> List[Row]
  emission fn execute(sql: Str) -> Int
}

component PgDatabase provides db: Database {
  config { url: Str, pool_size: Int = 10 }

  let pool = effect Pool.open(config.url, config.pool_size)
             undo   pool.close()

  provide db {
    fn query(sql)   = pool.query(sql)
    fn execute(sql) = pool.execute(sql)
  }
}

component UserCache requires db: Database provides cache: Cache {
  let store = effect Map.new() undo store.drop()

  provide cache {
    fn get(key) = store.get(key)
    fn put(key, value) {
      effect store.insert(key, value)
      undo   store.remove(key)
      emit db.execute(`INSERT INTO cache_log VALUES (${key})`)
    }
  }
}
```

## Services

- `service Name { ... }` declares an interface. Operations:
  - `fn name(param: Type, ...) -> Type` — an ordinary (read/effect) operation.
    The return type is optional.
  - `emission fn name(...) -> Type` — an operation that is *irreversible*
    (leaves the system boundary). Callers must invoke it with `emit`.
- A declaration is an **upper bound on its providers**: an operation declared
  plain `fn` may not be implemented by a body that reaches an emission. If an
  operation is meant to emit, declare it `emission fn` in the service.
- Types: `Str`, `Int`, `Float`, `Bool`, `Opt[T]`, `List[T]`. Other capitalized
  names (e.g. `Row`) are accepted as opaque types.

## Components

Header: `component Name requires a: ServiceA provides b: ServiceB { ... }`
— zero or more `requires`, zero or more `provides`, in that order.

Body statements (in order of appearance, all optional):

- `config { name: Type, other: Type = default }` — deploy-time parameters,
  read as `config.name` in expressions. At most one config block, first.
- **Named acquisition**: `let x = effect EXPR undo EXPR` — runs the effect,
  binds the result to `x`, registers the inverse. The `undo` expression may
  use `x`.
- **Anonymous effect**: `effect EXPR undo EXPR` — same, without a binding.
- **Emission**: `emit svc.op(args)` optionally followed by
  `compensate svc.op(args)` — calls an `emission fn`; the compensation is a
  saga-style best-effort counteraction run if later steps are reverted.
- **Boundary**: `await Job.run(arg)` — an async host job; the runtime may
  divert (hot-swap) at this point, reverting only the effects accumulated so
  far.
- `provide name { ... }` — implements a service declared in `provides`.
  Methods:
  - `fn op(params) = EXPR` — expression form.
  - `fn op(params) { ... }` — block form; the block may contain
    `effect ... undo ...` statements and `emit svc.op(...)` statements.
  - A method implementing an `emission fn` must have a body that emits, e.g.
    `fn log(msg) { emit db.execute(msg) }`. The converse also holds: a method
    implementing a plain `fn` may not contain an `emit` — declare the service
    operation `emission fn` instead.
  - A call made for its effect needs a binding: write
    `let _ = kv.put(k, v)`, not a bare `kv.put(k, v)` — a plain call is not a
    statement.

## Expressions

Keep expressions simple: literals (`1`, `"text"`, `true`), identifiers,
`config.field`, calls `f(a, b)`, method calls `x.m(a)`, and **backtick
template strings** `` `INSERT ${key}` `` for interpolation. Plain
double-quoted strings do **not** interpolate — never write `"$name"`.

Host constructors (built-in stub objects, usable in `effect` expressions):
`Pool.open(url, size)` / `pool.close()` / `pool.query(s)` / `pool.execute(s)`,
`Map.new()` / `m.get(k)` / `m.insert(k, v)` / `m.remove(k)` / `m.drop()`,
`Job.run(x)` (only under `await`).

## The rules the compiler enforces (guarantees)

- **G1**: a component may only touch services bound in its own `requires`
  list. Referencing anything else is a compile error.
- **G4**: every acquisition must carry an `undo`; irreversible operations must
  be declared `emission fn` and called with `emit` (optionally
  `compensate`). Calling an emission without `emit` is an error, and so is
  reaching one from the body of an operation the service declared plain.
- `undo` must be a single call expression — it cannot register new effects.
- `provide` blocks must implement exactly the operations of the service.
- Two components may not provide the same service name (G2), and requirement
  graphs must be acyclic (G3).
