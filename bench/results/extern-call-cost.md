# Host extern call cost, Python tier (issue #2709)

Generated by `python3 bench/extern_call_cost.py --write`. Python 3.12.12 on Darwin 25.2.0 (arm64), cordis-py 4.0.0.

CPU time per call (`time.process_time_ns`), so a machine busy with
other work moves wall time and not this table. Reproduce with:

```sh
sh backends/python/setup.sh
python3 bench/extern_call_cost.py --write
```

| call | median CPU ns/call |
|---|---:|
| direct body (pure) | 73 |
| pure extern | 90 |
| direct body (witnessed) | 350 |
| latch path read | 1449 |
| E-Stop gate | 1664 |
| witnessed extern | 2174 |
| session entry (with its gate) | 4003 |
| provide method | 8525 |

CPU time per call, empty loop subtracted (78 ns/call). 7 samples x 20,000 calls per arm.

What the arms say: the pure extern costs 17 ns over its body, so a pure call is the same call the host would make. The boundary crossing costs 1824 ns over the witnessed body (the E-Stop gate alone is 1664 ns, of which the latch-path read is 1449 ns). The session entry row is 4003 ns and includes the gate its own registration checks, so the entry alone is about 2339 ns. The full provide-method crossing is 8175 ns over the body (23.4x the body). It pays the E-Stop gate twice, once in the witnessed wrapper and once in the registration, and adds the session entry and the pure call; those parts sum to about 5918 ns while the crossing measures 8175 ns, so the 2258 ns residual is the allocation at the emitted call site (two lambdas, a scope dict and a call dict per call) plus timing noise, not a part the table can name. The capability check is compile-time (G4) and has no per-call arm; the WAL discharge record (the audit record) is not on this path either: no arm attaches a recorder, so `Frame._wal()` is None and no descriptor is written.
