# `revl scaffold`

**Status:** implemented (2026-08-26). Companion to docs/holes.md — that
document owns the `hole` construct and the scaffold-then-fill loop (§8); this
one owns the command that writes the scaffold.

Agents and humans write top-down, and a hole is what lets them (docs/holes.md):
a placeholder that has a type, satisfies the checker, and is recorded as an
unmet obligation. `revl scaffold` is the front half of that loop. It takes a
small spec and writes a well-typed `.rvl` skeleton whose not-yet-known
expressions are already holes, so the work that remains is *fill this hole*, one
bounded local decision at a time, rather than *write a plausible whole file and
find out at admission what was wrong*.

The generator invents structure, never finished code. It writes the service
contract, the component wiring, and the acquire/undo scaffolding of an effect;
everything a real decision belongs to becomes a `hole[T]` the compiler tracks.

```
revl scaffold --service Analysis --requires filesystem \
  --provides analysis --capabilities filesystem.read --out csv_analyzer.rvl
```

writes `csv_analyzer.rvl`:

```revl
// Scaffold generated by `revl scaffold` (docs/scaffold.md).
// Every `hole[T]` below is an open obligation: this file compiles as a
// draft, but admission refuses it until each hole is filled (docs/holes.md).

// TODO: declare the operations Filesystem must offer.
service Filesystem { }

service Analysis {
  emission[filesystem] fn run(input: Str) -> Str
}

component AnalysisProvider requires filesystem: Filesystem provides analysis: Analysis {

  // The acquire/undo scaffolding is real; the resource it yields is an obligation.
  let resource = effect hole[AnalysisResource] "acquire the resource AnalysisProvider manages; the undo must fully release it (no residue)"
                 undo resource.release()

  provide analysis {
    fn run(input) = hole[Str] "produce run's Str result (a fill here may emit through the declared boundary)"
  }
}
```

It compiles as a draft (the holes check) and is never admissible while a hole
remains (admission refuses holes, docs/holes.md §4). Fill the holes, then admit.

## Flags

| flag | meaning |
|---|---|
| `--service NAME` | the service the component provides (required) |
| `--provides KEY` | the provision key (default: the service, lowercased) |
| `--component NAME` | the component name (default: `<Service>Provider`) |
| `--requires KEY[:Service]` | an injected dependency; repeatable. A bare `KEY` defaults its service to `KEY` capitalized |
| `--capabilities CAP` | a boundary the component may emit through; repeatable |
| `--method 'name(p: T) -> R'` | a pure service method; repeatable |
| `--emits 'name(p: T) -> R'` | an emission service method, bound to the wired capabilities; repeatable |
| `--config name:Type` | a component config field; repeatable |
| `--resource Type` | the effect-acquired resource's type (default: `<Service>Resource`) |
| `--no-effect` | omit the acquire/undo effect block |
| `-o, --out PATH` | write the skeleton here (default: stdout) |
| `--json` | print the skeleton, its obligations, and each hole's fill spec as one document |

Every method needs a return type. A provide body is `= hole[R]`, and a hole
takes its type from context (docs/holes.md §2); the return type is that context.
With no `--method` and no `--emits`, the scaffold writes one entry point,
`run(input: Str) -> Str`, so the one-line spec above still yields a useful
skeleton.

## Conservative by construction

The safety property of the language applies to the tool that writes the
language: the generator never grants authority the spec did not ask for.

* **Only the declared capabilities.** The skeleton declares exactly the
  boundaries the spec names and no others. There is no default `emission`, no
  auto-widening to `network` or `filesystem.write`, nothing implicit.
* **An emission bound only for an injected boundary.** A capability names the
  boundary a crossing goes through, and that boundary is a requirement key
  (docs/capabilities.md §2). `emission[C]` is written only when `C`'s boundary
  is injected by `--requires`. The root of a dotted label like `filesystem.read`
  is `filesystem`; the `.read` refinement is below revl's capability
  granularity, so it survives in the obligation prose as documentation, not as a
  distinct capability, and the bound stays exactly `filesystem` — the boundary
  the spec injected, never wider.
* **A missing boundary stays a hole, not a permission.** If the spec asks for a
  capability whose boundary it did not inject, the generator does not invent the
  wiring. The operation that would need it is left as a pure `hole`, and the gap
  is named in the obligation message. The missing authority is a
  compiler-tracked obligation, which is the whole point: a fill that needs to
  cross that boundary cannot, until the spec is amended to grant it and the
  scaffold is regenerated.
* **An emission with nowhere to go is refused.** `--emits` with no wired
  capability would force a bare `emission` ("any boundary"). The generator
  refuses rather than write it.

## `--json`: the skeleton and its remaining work in one response

`--json` compiles the skeleton and returns it with its obligations, each
enriched with the same fill spec `revl_check` adds (docs/holes.md §8): the
expected type, the emission upper bound at that position, the bindings in scope,
and the reachable services. This reuses the check-and-obligation path the rest
of the toolchain already trusts; the generator is the only new code.

```json
{
  "ok": true,
  "source": "…the .rvl skeleton…",
  "holeCount": 2,
  "admissible": false,
  "obligations": [
    {"code": "T3", "expected": "AnalysisResource", "line": 15, "message": "…",
     "fillSpec": {"expected": "AnalysisResource",
                  "capability": {"mayEmit": false, "bound": [], "reason": "…"},
                  "bindings": [], "reachableServices": []}},
    {"code": "T3", "expected": "Str", "line": 19, "message": "…",
     "fillSpec": {"expected": "Str",
                  "capability": {"mayEmit": true, "bound": ["filesystem"],
                                 "reason": "an emission-declared provide-method scoped to filesystem"},
                  "bindings": [{"name": "input", "type": "Str"}],
                  "reachableServices": []}}
  ]
}
```

`admissible` is the standing verdict: a scaffold with open holes never is. An
agent reads the skeleton, fills one hole against its spec, re-checks, and
repeats until `holeCount` reaches zero.
