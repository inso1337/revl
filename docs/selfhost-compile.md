# The capstone: the integrated native `revl_compile`

Roadmap items 224 → **230** → **262**. The self-host effort ported the compiler one
pass at a time (`selfhost/lexer.rvl`, `parser.rvl`, `checker.rvl`, `lower.rvl` for
the frontend, `emit_py.rvl` / `emit_rust.rvl` for the tail), each a **differential
oracle** against the reference. This is the payoff: `selfhost/compile.rvl`, the
driver that composes those stages into **one co-compiled revl-native pipeline**,
and `tests/test_selfhost_compile.py`, which proves the composed chain produces
target source **byte-for-byte identical** to the reference `backends/<tier>/emit.py`,
**with no reference anywhere in the chain**, for **both the module-function + type
surface and the component + extern surface**, on **all six tiers** (py, ts, go,
java, rust, wasm) as of roadmap item 146 gap 2.

Item 224 shipped this as a *front half* with two named seams (a reference IR in the
middle; the stages could not co-compile). **Item 230 closed both** for the function
surface, on top of item 232 (the native IR producer `lower_to_ir`) and item 228
(private decls stopped leaking across `use`). Items 242 + 241 then made
`lower_to_ir` **complete** for the typed component/method body and the `@backend`
extern bodies, and **item 262** proved the same fully-native pipeline compiles
component and extern programs end to end, byte-exact, no reference in the chain.
This note states precisely what "revl compiles itself" means now: the covered
surface is native end to end, and the typed component body is no longer a
reference-only remainder.

## The pipeline (all native, one artifact)

```
source ──▶ admit_src (lower.rvl)          the native FRONTEND admission gate:
                                          lexer.rvl → parser.rvl → checker →
                                          lowering ADMISSION gate. "" admits,
                                          "<TAG>|<msg>" refuses. The one revl
                                          promise, enforced before any emit.
       ──▶ lower_to_ir (lower.rvl)        the native IR PRODUCER (items 232,
                                          242, 241): source → interchange IR
                                          (JSON), byte-exact vs the reference
                                          lowering across functions, types,
                                          components and externs.
       ──▶ json_parse (stdlib/json.rvl)   JSON text → the `Any` value the
                                          emitters navigate (stdlib/value.rvl).
       ──▶ emit_<tier>_src                 the native EMITTER, dispatched on tier:
           (emit_{py,ts,go,java,             IR → target source, byte-exact vs the
            rust,wasm}.rvl)                 reference emitter. All six tiers.
```

`compile.rvl` `use`s `lower.rvl` (which itself `use`s `lexer.rvl` + `parser.rvl`)
and **all six** `emit_<tier>.rvl` files in **one composition** (roadmap item 146,
gap 2). `compile_to(source, tier)` runs the whole chain in that one artifact:

- unsupported tier → `UNKNOWN_TIER|<tier>`
- the native gate refuses → `REFUSED|<TAG>|<message>` (the IR producer and emitter
  never run: a program the checker rejects cannot be compiled, the one revl
  promise, enforced natively)
- `compile_to_at` only: a `use` the native link cannot reproduce →
  `REFUSED|LINK|<message>` (issue #2181; the producer has run, the emitter never
  does, so no source that differs from the reference is returned)
- admitted → **the emitted target source**, `lower_to_ir(source)` → `json_parse`
  → `emit_<tier>_src`, byte-exact with the reference compile for the covered
  surface. A control verdict never collides with real output: py source begins
  `"""Generated by the revl cordis-py backend …`, rust `//! Generated by the revl
  cordis-rs backend …`, ts `// Generated by revl backend …`, go `// Code generated
  by backends/go/emit.py …`, java `// Generated by the revl cordis4j backend …`,
  and wasm `;; Generated by the revl cordis-wasm backend …`.

### Multi-file input: `compile_to_at(source, tier, path)` (issue #2093)

`compile_to(source, tier)` takes **one source string**, so it cannot resolve the
`use` declarations that string carries: a document such as
`src/revl/truc/components/cli.rvl`, which imports the `Assembler` and `Shipper`
service tables from sibling files, compiled through the native chain lost exactly
those two rows. The reference loader (`revl.compiler._ModuleLoader.resolve_use`)
resolves them, and the reference `services` table for that document is
`Cli`, `Assembler`, `Shipper`: the document's own service plus its **direct**
imports, appended last. That is a harness/API limitation of the entry point, not
a `lower.rvl` defect: `lower_to_ir` never sees the imported files, so no lowering
change can recover them.

`compile_to_at(source, tier, path)` is the same chain with the document's own
path, which is what the resolution needs:

- `path` is `""` gives an output **identical** to `compile_to` (byte-for-byte, no
  filesystem access at all). `compile_to` is now exactly
  `compile_to_at(source, tier, "")`.
- `path` non-empty means that, before emitting, the driver scans `source` for
  top-level `use "target" { A, B }` declarations (column 0, so a commented or
  indented `use` is not one), reads each target **relative to the importing
  document** (one `pure @py` extern read, the same host boundary
  `stdlib/auth.rvl`'s `host_validate` uses: a read, with no accounted mutation),
  lowers it, and splices the named services it declares into the IR's `services`
  table **after** the document's own rows. A name already present in the output is
  left alone, so a diamond import is not duplicated and an import that is not a
  service is a no-op.
- Then the driver links externs (issue #2181). The reference `compile_files`
  merges every module whose pure declarations the document imports (a `pub fn`,
  `type` or `extern` named in a `use` list, transitively) and appends that
  module's whole `extern` section, so `use "stdlib/json.rvl" { json_parse,
  json_stringify }` also carries `json_try_parse`. `ul_link_externs` builds the
  same closure (breadth first from the document, each module's dependencies
  sorted by absolute path, each module once), lowers each module and appends its
  externs after the document's own, creating the `externs` array when the
  document declares none. A module imported only for a service adds no extern.
  Where the result would differ from the reference, the driver returns
  `REFUSED|LINK|<message>` instead of emitting different source:
  - an appended extern whose name the document already declares as an extern or
    function (the reference renames colliding private names apart, this driver
    does not);
  - a pure dependency that carries anything but externs, which the reference
    merges and this driver does not: any IR section beyond `ir_version`,
    `services`, `components` and `externs` (functions, types, secrets, tests),
    and any top-level declaration other than an extern, a `use`, a service or a
    component (a `prop test`, say, for which the producer writes no key at all);
  - a `use "m" as alias` import, which makes the whole module a dependency;
  - a dependency that declares externs none of which lowered natively.

  An extern declaration is read as a whole, host bodies included, so a
  column-0 line of host code inside `@py { ... }` is not taken for a
  top-level declaration of its own (issue #2308). The body is scanned as the
  self-host lexer scans it (brace depth, `"` strings skipped), not as the
  reference lexer does; a body whose brace sits in a `'` string or a comment is
  misread by both self-host scans alike, its externs do not lower, and the
  module is refused.
- Last, the driver links the types an imported service carries (issue #2308).
  A `use "./lib.rvl" { Store }` that names only a service makes no pure
  dependency, but the reference's `compile_files` still brings the PUBLIC record
  and variant types the service's operations name, closed over the types their
  fields and case payloads name (its `carried` list, issue #1899), and appends
  them to the merged `types` table after the document's own. `ul_link_types`
  does the same, in the module's declaration order, each type once, and sets
  `ir_version` to 3 as a type table does in the reference. A private type of
  the document with a carried type's name is renamed apart to `<name>__m0`
  before the document is lowered, as the reference's privacy pass renames it
  (`ul_rename_apart`, issue #2374): every identifier of that name outside
  comments, strings, templates and host bodies, provided the document's IR
  holds the name only as a type (not as a case, a record field or another
  declaration), no service or component of the document names it (the
  reference's `_rewrite_module` never renames there), and the document does
  not import it by name. It refuses with `REFUSED|LINK|` where a document's
  own type of a carried name is public or could not be renamed that way, where two modules carry one name, and where
  any type the service's module declares, public or private, has no native
  `types` entry.
  The last covers a transparent alias (`pub type Al = Cell`, or a private
  `type Id = Int`): the producer expands it in the service row and in record
  fields and writes no entry for it, so the link would carry `Cell` where the
  reference carries `Al`, or print `id: Int` where the reference keeps `id: Id`.
  The module's type declarations are found by token at bracket depth 0, at any
  column, so an indented declaration or a second one on the same line counts.
  The native producer does not lower that second one, so such a module is
  refused. The scan reads the text the way the reference lexer does
  (`src/revl/lexer.py`): `//` comments, `"` and `'` strings with only the
  `\<quote>` and `\\` escapes, `"""` strings, backtick templates and their
  `${...}` interpolations, and `@backend { ... }` host bodies under that
  backend's string and comment rules. A brace or quote inside any of them does
  not move the scan. It fails closed: an unterminated string, template or host
  body, a bracket closing below depth 0, an unclosed bracket, or a `type`
  keyword inside brackets refuses the link, since the reference rejects all of
  them. A `pub verified type` or `pub endorse[...] type` is read as public (the
  native producer lowers neither, so that link refuses too).
- Once the link succeeds, the driver types the document's calls to the
  services it imports (issue #2329). `admit_src` reads only the document, so a
  `store.put("x")` against a `put(id: Int)` declared in the imported module used
  to be admitted and emitted, where the reference checker refuses it.
  `tc_admit_imports` admits the document again with the declaration text of
  every imported service appended (from `service` to its closing brace, found
  by the same reference-lexer scan; a leading `pub` or `commutative` is left
  off), and returns that verdict as `REFUSED|<TAG>|<message>`, the reference's
  own message where the gate types the call the way the reference does. The
  module's type declarations are not appended. The gate types a built-in
  parameter type, and a carried record or variant by name, without them. A
  transparent alias never reaches this pass: the type link above refuses a
  module that declares one, which is what refuses the issue's reproducer (a
  private `type Id = Int` parameter). It refuses with `REFUSED|LINK|` where
  the appended text would type the calls differently: a service the native IR
  has a row for whose text the scan cannot read, and a declaration that names
  a type the document also declares (any identifier of the declaration text
  counts, so a parameter or comment word of that spelling refuses too). The
  types the service carries (its record and variant types, issue #2362) are
  appended too, rendered from the module's native `types` table, so the gate
  can hold a record literal to a carried record parameter field-wise. A
  generic carried type is left out.
- A carried variant's case named in a component body (`store.draw(Dot)`,
  `Box(1)`) is unknown to the document read alone, which refuses it with G1
  as an undeclared requirement. The reference resolves it through the carried
  type (issue #2374). So a G1 of the document read alone is decided again on
  the document with the declaration text of every carried type appended
  (`tc_carried_admission`), and when that admits, the document is lowered with
  the same text, so its IR has the reference's `adt` nodes and the carried
  types in the reference's order; the type link then appends none of them
  twice. When a carried type has no declaration text (a generic one), or the
  document declares or imports one by name, the G1 stands. A case of a type
  no operation carries (a private one, or a public one the service does not
  name) stays a G1, as in the reference.
- The gate's own call-site rules, in a single document and through an import
  (issue #2362):
  - A requirement call with the wrong number of arguments is refused with the
    reference's ``store.put` takes 1 argument(s), 2 given``.
  - A record literal passed for a nominal record parameter is held to the
    record's fields (the same field set, each compatible) through the `field
    <Type>.<name>` rows. A record named inside a field type, whole or as a type
    argument (`In`, `Opt[In]`, `List[In]`), is expanded the same way, four
    levels deep. So is a record named in a container parameter (`put(r:
    Opt[Row])`, `put(r: List[Row])`), so `store.put([{ id: "x" }])` gets the
    reference's argument message.
  - A record literal passed for a variant parameter is refused with the
    reference's argument message.
  - A requirement call is typed at its operation's declared return wherever
    it appears (`reqret <root>.<op>` rows), so `= store.put(1) + 1` is held to
    the method's result like any other value.
  - A `fn m() = <expr>` provide method is typed as the `return <expr>` the
    reference makes of it, and a returned value's requirement calls are decided
    before the return's own check, in the reference's order.
  - Through an import, a T1 from the document read alone yields to the import
    admission's verdict when that refuses too, so the call's message wins as
    it does in the reference.

  Still refused differently from the reference (all refusals, none emits):
  - In a single document, a record literal for a generic record parameter
    (`Cell[Int]`) is refused by name (`TYPE|... is not typed by the native
    gate`), not typed.
  - A record literal nested past the shape expansion (more than five levels
    for a record parameter, four inside a container one) is refused by name
    (`TYPE|... nested deeper than 5 levels`), valid or not.
  - Through an import, an operator whose operand type only the imported
    declaration gives (`store.put(1) + 1` with `put -> Int`) is refused by
    name (`LINK|an operator on an imported service call's result ...`): the
    document is lowered without the declaration, so its IR would lack the
    `operands` the reference writes (the py tier's overflow guard). The
    check lowers the import admission text too and compares the typed
    operators. It refuses valid programs of that shape too (`= store.put(1) +
    1`, `+ n`, `let x = store.put(1)` then `x + 1`), because their native
    bytes would differ; typing the imported call in the IR would admit them.
  - A wrong argument count to an unmarked `emission` operation refuses with
    the wiring's G4 where the reference reports the count first.
  - Through an import, a record literal for a carried generic record
    (`Cell[T]`) gets a T1 where the reference admits (issue #2374).

This is the honest multi-file native compile: the whole chain still runs in revl,
and the only host crossing is the read the reference loader also performs. It
closes the `cli.rvl` entry on the py and go tiers. `tests/test_selfhost_compile.py`
drives it with `compile_to_at(source, tier, str(path))`; the ratchet's
`LOWER_GAP_DOCS` entries are what is left when it is driven that way.

Not a reimplementation of `REVL_IMPORT_PATH`: the search is importer-relative
with a bounded walk upward, which is what both `use`-carrying documents in the
corpus need (`cli.rvl` and `backends/typescript/tests/fixtures/fr3_json_int.rvl`
both resolve importer-relative). A document relying on an environment search path
is not covered.

Before anything is linked, every used module is admitted (issue #2332,
`compile.rvl::ad_used_modules_refusal`): depth first from the document, each
module once, its whole text is read by the self-host front end, and the first
one that does not read refuses the document with
`REFUSED|BAD|<module>: <message>`. As in the reference loader, a `use` target
that resolves to nothing refuses with `cannot find imported module`, and a
module reached again while it is still being read refuses with `import cycle`.
A program-grammar refusal names its line where one can be placed, and a
top-level expression-bodied fn (`fn f(x: Int) -> Int = x`, valid revl) is
named as not supported by the self-host compiler.

The admission runs the whole parse stage of the native gate
(`lower.rvl::parse_refusal`, issue #2359), the same steps `admit_src` runs on
the document: the foreign-construct redirects, the nesting limit, the program
grammar, and `stmt_parse_scan`, which reads the statement-level and type
declaration rules the reference parser raises and `parse_prog` does not
(`fail` outside an activation body, `await` in a sync method, lifecycle
statements outside a `lifecycle test`, `??` mixed with `||` or `&&`, a plain
access after `?.`, a dynamic realm label, an unclassified extern, the
computer-use teardown rule, a union alias, a keyword as a field name).

Known gaps of the admission:

- Admitting a used `selfhost/lower.rvl` or `selfhost/emit_rust.rvl` under the
  python tier's default recursion limit raises `RecursionError` instead of a
  named refusal: `parse_prog` recurses once per top-level declaration, the depth
  `admit_src` already has on those files.
- The upward walk above can find a module the reference does not (it has no
  ancestor search), and an imported name the module does not export is not
  refused; both are tracked in issue #2363.

## What is FULLY NATIVE now (functions, types, components, externs)

The proof (`test_native_compile_is_byte_identical_with_no_reference`) feeds
`compile_to` **only the raw source string** and compares its output to the
reference compile; the reference is used solely to compute the *expected* value,
never to produce the native output. A byte-for-byte match is therefore a proof the
whole lex→parse→check→lower→emit chain ran in revl.

Byte-exact, no reference in the chain:

- **py: 10/10 function documents** (`tests/fixtures/emit_py_corpus/`): `arith`,
  `control`, `strings`, `records`, `result`, `optionals`, `floats`, `mixed`,
  `hostroots`, `types`, the emitter-ready set item 232 proved `lower_to_ir`
  byte-exact on (every module `fn` with its full typed-expression body, and every
  user record/variant `type`).
- **rust: 5 function documents** (`tests/fixtures/emit_rust_corpus/`): `arith`,
  `control`, `lists`, `strings`, `variants`, the pure function / type / variant
  slice the rust emitter covers on the native IR.

The **component + extern surface** is byte-exact too (item 262), same pipeline,
same no-reference proof:

- **py: 7 documents** (`tests/fixtures/emit_py_corpus/`): `services_basic`,
  `services_config`, `services_body`, `services_methods`,
  `services_method_effects`, `services_timers`, and `externs`.
- **rust: 7 documents** (`tests/fixtures/emit_rust_corpus/`): `service`,
  `services_multi`, `requires`, `effect_emit`, `effect_undo`, `config`,
  `config_effect`.

These exercise required-service calls, effectful and emitting methods, `config`
reads, timers, and verbatim `@backend` extern bodies, all lowered natively by
`lower_to_ir` (items 242 + 241) and emitted natively by each tier's emitter.

Both former seams are **closed** for this surface:

- **SEAM 1 (the reference IR in the middle): gone.** `compile_to` produces the IR
  with the native `lower_to_ir` (item 232) and parses it with the native
  `json_parse`. `revl.compile_source` is no longer in the pipeline.
- **SEAM 2 (the stages could not co-compile): gone.** Item 228 stopped a `use`d
  module's **private** decls from leaking (so the stages' private `Ctx` /
  `node_kind` / `ind` / … no longer collide), and item 230 gave the two emitter
  entrypoints **distinct public names** (`emit_py_src` and `emit_rust_src`), so
  the merge, which flattens public decls by bare name, no longer sees a duplicate
  `emit_src`. Item 146 gap 2 completed the rename for the last three tiers, so
  `test_six_way_composition_co_compiles` is now the standing check that `lower`
  plus all six `emit_<tier>` files compile into one artifact. (Two duplicate
  in-file `test` names across the emitters, and one type name colliding with a
  stdlib type parameter, were disambiguated as part of the renames.)

**So: revl compiles itself end to end, natively, for the covered surface**,
functions, types, components and externs: lexer through emitter, one revl
composition, no reference bytes in the chain, byte-exact with the reference on py
and rust.

## What the reference is still used for (proof oracle, not pipeline)

The typed component body is no longer a reference-only remainder. Items 242 + 241
completed `lower_to_ir` for the typed component/method spine (component arithmetic,
stdlib builtins, `config` reads, `match`/ADT, saga `emit … compensate`, timers,
spawn) and the verbatim `@backend` extern bodies, and item 262 proved the composed
native pipeline compiles component and extern programs byte-exact with no reference
in the chain (the corpus above). The reference compiler is still present in the
test, but only as the **oracle** that computes the expected bytes; it never
produces the native output.

What remains is not the self-hosting question. It is native-tier runtime
**performance** (the rust self-host lexer's O(n²) `revl_push` clone-on-append,
roadmap items 283/284) and per-tier **run** coverage. The self-compile of the
covered surface is settled on all six tiers; widening that surface is a
`lower.rvl` question, measured above.

## Compiling `emit_rust.rvl` itself to rust (native `compile_to` Stage 4, #106/#98)

Running the rust emitter when it is COMPILED TO RUST (not just producing rust from
the py-hosted emitter) needs every host-formatting extern in `selfhost/emit_rust.rvl`
to carry an `@rs` body. All six now do: `newline`/`mangle`/`snake`/`camel` landed
first, and `string_lit`/`num_str` are now ported too. The `Any`-typed pair recovers
the erased value the way the whole rust tier does, a boxed `serde_json::Value`
reached through `v.downcast::<serde_json::Value>()` (the `stdlib/value.rvl` /
`stdlib/json.rvl` model). `num_str`'s float path is a shortest-round-trip formatter
that reproduces Python's `repr(float)` (fixed vs scientific by the same decimal-point
rule, trailing `.0` on whole-valued fixed forms); it and `string_lit`'s non-ASCII
branch carry the same cross-tier caveat `json.rvl` already documents for floats.

The one required emitter change is the concrete-to-`Any` boxing coercion at the call
site (`backends/rust/emit.py::_coerce_any_arg`): a concrete `Str`/`Int`/`Int32`/
`Float`/`Bool` argument flowing into an `Any`/`Value` parameter is wrapped as
`Value::new(serde_json::Value::from(..))`, which the many `string_lit(<Str>)` /
`num_str(<Int>)` call sites in this file need to typecheck against `fn f(v: Value)`.

Stage 4 is not yet fully reachable. With `stdlib/value.rvl`'s `@rs` accessors present
(the wave that carries them), `emit_rust.rvl` EMITS to rust with zero externs missing
an `@rs` body, but the emitted crate does not yet `cargo build`: the residual blockers
are all in OTHER self-host functions, not the escapers or the coercion.

Blocker (1), the `List[Any]`/`Vec<Value>` `.length()` ergonomics gap, is now
CLOSED. `revl_length`/`revl_slice`/`revl_concat`/`revl_push` need only `T: Clone`;
only `revl_index_of` compares elements and so needs `T: PartialEq`. The prelude
(`backends/rust/emit.py::_stdlib_helper_traits`, mirrored byte-for-byte in
`selfhost/emit_rust.rvl`) now splits them: the size/copy ops stay on
`impl<T: Clone> RevlListOps<T>` and `revl_index_of` moves to a separate
`impl<T: Clone + PartialEq> RevlListSearchOps<T>`. A `Vec<Value>` (`cordis::Value`
is `Clone` but NOT `PartialEq`) therefore reaches `.revl_length()` and the other
size/copy ops - which the fused `T: Clone + PartialEq` bound rejected outright -
while `.revl_index_of()` on a `PartialEq` element type resolves exactly as before
(both traits are emitted together in every module's prelude). An isolation crate
over a `Vec<Value>` (`Clone`, non-`PartialEq`) compiles `length`/`slice`/`concat`/
`push`, and `revl_index_of` on a `Vec<i64>` is unchanged.

Blocker (2) is now CLOSED, and with it the build. Measured before the fix: the
emitted crate failed `cargo build` with nine `E0308`s and nothing else. All nine
were the same class, a concrete value reaching the opaque `Value` slot that `Any`
erases to with no boxing written at the crossing, in four distinct positions:

1. an ARGUMENT whose type the emitter could not infer. `_v3_infer_type` named no
   type for a `kind == "builtin"` node, so a `let` bound to a stdlib method call
   (`let inner = name.slice(a, b)`, `let joined = fmt.join("")`) carried none and
   `_coerce_any_arg`, which fires only on a known concrete scalar, passed the bare
   `String` through. `_v3_builtin_return_type` now names the result of the stdlib
   method table's unconditional rows, and resolves the `@self` rows
   (`slice`/`concat`/`push`/`set`/`remove`) through the receiver. `to_int` and
   `lookup` stay unnamed: their result depends on the receiver family or the map's
   value parameter, and a guess there would be a silent representation change;
2. a RETURN into a declared `-> Any`. The same erasure, the same `E0308`, and the
   coercion was wired at argument positions only;
3. an `Opt[Any] ?? <scalar>` DEFAULT. `unwrap_or_else` has to yield the `Value`
   the `Option` carries;
4. a `List[Any]` ARGUMENT. A `Vec<Value>` whose elements already hold the erased
   `serde_json::Value` boxes as the JSON array `stdlib/value.rvl`'s `value_list`
   reads back, which is the exact inverse of that accessor. It is the ONE
   container admitted: `List[Str]`, `List[Int]` and the rest hold `String`/`i64`,
   not `Value`, so there is no element-wise recovery to invert.

With those four landed, `selfhost/emit_rust.rvl` emitted to rust `cargo build`s
clean. `tests/test_selfhost_emit_rust.py::test_the_rust_emitter_builds_as_rust`
holds it, running the build rather than inferring it from byte-exact emit, which
is the item-266 lesson.

### Driving it: the rust-side IR constructor

Building is not running, one level up from the item-266 lesson. The emitted
emitter's entry takes the interchange IR as an `Any`, which erases to the opaque
`cordis::Value`, and nothing a generated `main` can spell builds one of those.

The constructor for that slot already shipped: `stdlib/json.rvl::json_parse`,
whose `@rs` body is `Value::new(serde_json::from_str::<serde_json::Value>(&s)..)`
i.e. the same boxing `stdlib/value.rvl`'s `@rs` accessors downcast back out. What
was missing was the COMPOSITION, and it is a revl document, not rust:

```
use "selfhost/emit_rust.rvl" { emit_rust_src }
use "stdlib/json.rvl" { json_parse }

pub fn drive(ir_text: Str) -> Str { return emit_rust_src(json_parse(ir_text)) }
```

`tools/bench_selfhost_rust.py::driver_document` generates exactly that, which
turns an IR-consuming emitter into a `Str -> Str` filter a generated `main` - or
any embedder - can call. One stage earlier, `selfhost/lower.rvl::lower_to_ir`
already renders the IR as JSON TEXT, so the same composition spells the WHOLE
native chain: revl source in, rust source out, in one binary. That is what
`selfhost/compile.rvl::compile_to` is on the py tier; compile.rvl itself cannot
be emitted to rust, because it `use`s `emit_py.rvl` and that emitter's
CPython-only `py_repr` extern has no `@rs` body.

Two gates hold the result, each checking that the comparison it just passed is
capable of failing (a byte comparison that cannot fail is not evidence):

* `test_the_rust_emitter_runs_as_rust_and_matches_the_reference` - the emitter,
  run natively over the whole byte-exact corpus, emits the reference's bytes;
* `test_the_whole_native_chain_runs_as_rust_and_matches_the_reference` - source
  in, rust out, over the subset `tests/test_selfhost_compile.py` already holds
  the native chain to (its `RUST_FUNCTION_DOCS` + `RUST_COMPONENT_DOCS`; the rest
  of the emitter corpus is excluded there for the same reason, the native IR
  producer rather than the emitter being the frontier).

`tools/bench_selfhost_rust.py` therefore measures the `emit_rust` stage natively
instead of recording it unmeasured. `emit_py` stays unmeasured, with the `py_repr`
refusal as its reason.

One manifest requirement comes with this. `stdlib/value.rvl`'s `value_keys` /
`value_children` read a record's fields in INSERTION order, which `serde_json`
preserves only under its `preserve_order` feature (its default map is sorted), so
`backends/rust/emit.py::cargo_toml` now enables it. Measured, not assumed:
without it, 10 of the 34 emit_rust corpus documents - the record-shaped ones -
emit rust that differs from the reference's when the emitter is RUN.

What Stage 4 still needs after this is no longer an emit gap:

* `crates/revl-gate` generates the FRONTEND only (`selfhost/lower.rvl` and its
  `use` closure), so the emitter is not in it. Its `compile_to` names what each
  tier is missing;
* `selfhost/emit_rust.rvl` does not mirror `_coerce_any_arg`, so no byte-agreement
  corpus document can reach the four crossings above without flipping the oracle
  red. They stay recorded in `tests/fixtures/selfhost_uncovered_lines/` with
  that reason, which is the same shape the boxing coercion already carried.
