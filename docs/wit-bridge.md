# The Component Model bridge — WIT export, and WIT resources

**Status:** Slices 1 and 2 implemented
(`src/revl/export_wit.py`, `src/revl/import_wit.py`,
`tests/test_export_wit.py`, `tests/test_import_wit.py`) · roadmap item 41 ·
companion to docs/import-wit.md and docs/interop-bridge.md

A revl wasm component today runs on one host (cordis-wasm). The WASI Preview 2
**Component Model** is the industry's standard container, and WIT
(WebAssembly Interface Types) is its interface language. This bridge crosses to
it in honest, independently-useful slices — interoperability *documentation*
before any binary compatibility.

| Slice | What | Status |
|---|---|---|
| **1** | `revl export wit` — the standard WIT interface of a revl service/composition | **done** |
| **2** | WIT `resource` support in the importer | **done** |
| **3** | canonical-ABI emission (a standard WASI P2 **binary**) | horizon — see §5 |

The claim the slices build toward: **WIT describes shape only.** A WIT
interface says what an operation is named, what it takes, and what it returns —
and nothing about whether it can be undone, where it may reach, or how it is
torn down. A revl-authored component is the first standard component whose
lifecycle and effects are *verified* — carried as metadata **alongside** the
WIT, because a WIT type cannot hold them.

---

## 1. `revl export wit` — the reverse of `revl import wit`

```
revl export wit <files> (--service NAME | --composition) [--package NS:NAME] [-o out.wit]
```

It compiles the revl sources and runs the importer's type mapping (docs/import-wit.md §2)
**backwards**, over the IR, to print the WIT interface the service or
composition presents. Pure codegen: no runtime, no emission, no binary.

- `--service NAME` exports one service by name.
- `--composition` exports every service the composition *provides* — its
  surface, the same set `revl serve` and `revl mcp schema` project.

```console
$ revl export wit greeter.rvl --service Greeter
```

```wit
// Generated by `revl export wit` — the standard WIT shape of a revl
// service/composition (docs/wit-bridge.md). ...
package revl:exported;

/// revl service `Greeter` as a WIT interface.
interface greeter {
  /// @revl:pure
  greet: func(name: string) -> string;
  /// @revl:emission (WIT carries no effect; verified alongside)
  log-greeting: func(name: string, at-millis: s64);
}
```

### The reverse type mapping

The rows of docs/import-wit.md §2, read right-to-left:

| revl | WIT | note |
|---|---|---|
| `Str` | `string` | |
| `Bool` | `bool` | |
| `Int` | `s64` | import had collapsed every integer width to `Int`; the widest signed spelling comes back |
| `Float` | `f64` | |
| `Bytes` | `list<u8>` | |
| `List[T]` | `list<T>` | |
| `Opt[T]` | `option<T>` | |
| `Result[T, E]` | `result<T, E>` | a `Unit` arm reverses to `_` / bare `result`: `Result[Unit, E]` → `result<_, E>`, `Result[T, Unit]` → `result<T>`, `Result[Unit, Unit]` → `result` |
| `Map[K, V]` | *refused* | WIT 0.2 has no map type; the exporter names it rather than inventing one |
| `type R = { … }` (record) | `record r { … }` | fields snake → kebab |
| `type V = A(T) \| B` (variant) | `variant v { … }` | |
| a payload-free variant | `enum e { … }` | the natural reverse of `enum → variant` on the way in |
| resource handle (§3) | `resource r { … }` | |

Names cross back: PascalCase types and cases become kebab-case
(`InStock` → `in-stock`), snake_case operations, params and fields become
kebab-case (`log_greeting` → `log-greeting`).

### Round-trip stability

`import wit` → revl → **`export wit`** → revl round-trips: the second revl's
service signatures, type declarations, and resource set match the first's.
`tests/test_export_wit.py::test_import_export_round_trip_is_stable` proves it
over the greeter, catalog and resource fixtures. What does *not* round-trip is
the number width (`u32` → `Int` → `s64`) — that loss happened on import, and
the header says so.

## 2. WIT carries shape, not effects — the metadata that rides alongside

This is the interesting half. revl's `emission` is a *checked* claim: a service
declaration is an upper bound on every provider (G4), which is what makes a
consumer's G8 audit meaningful. WIT's `func` cannot express it — `read: func()`
and `delete-everything: func()` are indistinguishable to it.

So the exporter carries revl's verified lifecycle as `/// @revl:*` doc
comments, **beside** the WIT shape, not inside it:

| revl fact | how it is carried | round-trips? |
|---|---|---|
| a plain (revertible) operation | `/// @revl:pure` | **yes** — the importer reads it back into a plain `fn` |
| `emission` | `/// @revl:emission` | no — re-import defaults to `emission` anyway (WIT still said nothing) |
| a capability scope `emission[db]` | `/// @revl:emission [db]` | no — advisory |
| `async` / `commutative` | `/// @revl:async` / `/// @revl:commutative` | no — advisory |
| an `extern acquire`'s `undo` inverse | the WIT `resource` destructor (§3) | structurally |

A standard WIT toolchain reads those comments as prose; a revl-aware one can
recover them. Only `@revl:pure` becomes a classification again — the rest are
advisory *because WIT's type system has nowhere to put an effect*. That is the
precise sense of the claim: the verification rides alongside the WIT, it is not
*in* the WIT.

## 3. WIT `resource` support (Slice 2)

The importer used to refuse `resource` — which locked out every real WASI
world, since a resource (a `wasi:filesystem` descriptor, a `wasi:sockets`
socket) is their central abstraction. But revl already has that abstraction at
its seams. From docs/interop-bridge.md and `src/revl/distribute.py`:

> A *resource type* is a value returned by an `extern acquire` (a `Socket`, a
> pool: a handle whose lifetime is tied to the providing fiber, so it crosses
> **by proxy, not by copy**).

A WIT resource maps onto that nearly one-to-one:

| WIT | revl | why |
|---|---|---|
| `resource r` | `type R = { handle: Int }` | an opaque proxy; identity lives host-side |
| `constructor(…)` + implicit destructor | `extern acquire fn r_new(…) -> R undo r_drop(result)` + a declared `extern emission fn r_drop(self: R)` | the resource's release is a **tracked inverse** (G4); `result` is the undo slot's implicit binding — the acquired handle |
| a method `m: func(…)` | a service op `r_m(self: R, …)` | the handle is the first parameter; it crosses by proxy |
| `static s: func(…)` | a service op `r_s(…)` | no handle |
| `borrow<r>` / `own<r>` in a signature | the handle type `R` | copy-vs-move is the host concern the acquire/undo pair already tracks |

```console
$ revl import wit tests/fixtures/wit/resource.wit
```

```wit
// (input) --------------------------------------------------------------
interface filesystem {
  resource descriptor {
    constructor(path: string);
    read: func(len: u64) -> list<u8>;
    /// @revl:pure
    tell: func() -> u64;
  }
  open: func(path: string) -> descriptor;
}
```

becomes an opaque handle, an `extern acquire` whose `undo` is the destructor,
and a service whose methods take the handle as `self`. `distribute.py` then
classifies the service `address-space-bound` — it names the `Descriptor` that
crosses — exactly as it does for a hand-written `extern acquire`. And the
resource round-trips: exporting the imported service reconstructs the
`resource descriptor { constructor(…); read; tell }` block
(`tests/test_export_wit.py`).

What WIT still cannot carry across this mapping is the `undo` itself as a
*verified inverse*: WIT records that a resource has a destructor, but not that
revl has proven the destructor makes the acquire revertible (G4). That proof is
metadata alongside the component, §2 again.

## 5. Slice 3 — canonical-ABI emission (the named, gated horizon; NOT built)

The next slice is turning this WIT plus a revl component into a **canonical-ABI
WASI Preview 2 binary** — a component another Component Model host can load
without knowing it was revl. This slice is deliberately **not** built here, and
this bridge touches no `backends/*/emit.py`.

It is gated. The cordis-wasm tier is i32-only today: `backends/wasm/emit.py`
raises hard `EmitError`s for `Str`, records and lists ("type 'Str' is not
lowerable — the cordis-wasm tier is i32-only"). The canonical ABI is defined in
exactly those types, so canonical-ABI emission cannot land before the wasm tier
grows non-i32 lowering. Until then, a WIT interface carrying strings, records or
lists exports and imports as perfectly good revl (Slices 1 and 2) that the wasm
emitter still cannot lower — which is why this bridge stops at the interface
text and says so.
