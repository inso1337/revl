ERASE A TRANSPARENT TYPE ALIAS AT EVERY DECLARATION SITE THE REFERENCE ERASES IT AT (2026-09-18, self-host lane; issue #1148).** `lower_to_ir` did not erase a transparent type alias at a declaration site: a fn declared `-> Count` where `type Count = Int` projects `"returns": "Count"` where the reference projects `"Int"`, because `_resolve_type_aliases` (`src/revl/lower.py`) substitutes before the IR is written. Exit: `lower_to_ir` erases at every declaration site the reference erases at — return types first, then parameters, config fields and service method signatures — and a corpus document declaring a transparent alias enters the corpus, so the byte-agreement projection is no longer vacuous on this construct. Landed: PR 1150. Owner: TBD (issue #1148).

529. (issue #1157) **✅ LANDED (2026-09-19, PR 1159, merged `008a8a430`): a read inside a loop body counts as a reuse, and `loop_moves.rvl` passes `cargo check --all-targets`. THE RUST REUSE SIGNAL MUST SEE A LOOP BODY (2026-09-18, self-host lane; issue #1157).** `_body_multi_use` (`backends/rust/emit.py`) types a binding off its initialiser; a ternary initialiser is exactly the case it types as `None`, so `_by_value_arg` cannot tell `Copy` from non-`Copy` and falls back to a reuse signal that counts **textual** references and has no notion of a loop body executing more than once. A binding read exactly once textually but on every iteration is therefore emitted as a move and fails borrow-check (`E0382`); a type annotation does not help, because the emitter reads the type off the initialiser. Measured twice inside one PR, in two files, and avoided source-side both times rather than fixed — which was honest for that PR but left the trap armed until PR 1159. Exit: the reuse signal accounts for a read inside a loop body, and a ternary-initialised binding read once per iteration compiles on the rust tier. Landed: PR 1159. Owner: TBD (issue #1157).

530. (issue #1172) **✅ LANDED (2026-09-20, PR 1184, merged `b6666d17c`): a declared key with no block and no `realms(...)` route is refused as A9, naming the key and the component, and the A9 row in `docs/guarantees.md` states both directions. A DECLARED PROVISION WITH NO BLOCK MUST BE REFUSED (2026-09-18, checker; issue #1172).** `_lower_component` (`src/revl/lower.py`) enforces two things about provide blocks — every block key is in the `provides` clause (A9), and no key is installed twice — and never enforces the converse. Before PR 1184, `provided_keys` was read by the double-install check alone, so a component could declare `provides k: S` and install no block, and the linker admitted it as `k`'s provider, because G2's requirement closure and the G3 layering are computed from the clause. The runtime is honest — a consumer of `k` stays PENDING (R2) — but the failure surfaces one hop away from its cause and only at activation, so a composition that links can fail to start. This is why the A9 row claimed nothing about the converse until PR 1184: until the checker enforces it, "links" is a statement about declarations rather than about what the runtime will find. Exit: a component declaring a provision it installs no block for is refused at admission, naming the key and the component, and the A9 row can then state the converse. Landed: PR 1184. Owner: TBD (issue #1172).

531. (issue #1175) **✅ DECIDED AND LANDED (2026-09-20, PR 1185, merged `89e002b05`; PR 1436 extended it to every carrier): one `emit` marks one crossing, so an unmarked or a marked emission inside an `emit`'s arguments is refused under G4 and must be hoisted, stated in `docs/rejections.md`. PR 1537 in review (issue #1437) extends the marker requirement to an emission extern called outside an `emit`'s arguments. DECIDE WHETHER `emit` MARKS A SITE OR AN EXPRESSION (2026-09-18, language design; issue #1175).** Before PR 1185, `emit` lowered as a **region** marker: `emit a.send(b.fetch())` and `emit a.send(emit b.fetch())` produced the same step, so an emission in argument position was admitted with no marker of its own and a marker written there was erased. `revl audit` enumerates both crossings, so G8's surface is complete; what is unsettled is the marker **discipline**, and the two readings are not equivalent. Per crossing site — which is how `compensate` binds and how `docs/rejections.md#g4` reads — the unmarked inner emission should be refused and the inner marker kept, so an inner crossing has somewhere for the approval and intent-refinement checks to run (today they run on the head only). Per expression, the docs must say so and the inner marker is redundant or a documented no-op. The formal harness follows the checker, so whoever models the region semantics follows whichever way this is decided. Exit: the discipline is decided, stated in `docs/rejections.md`, and the corpus carries a fixture for the refusal the decision implies. Landed: PR 1185. Owner: TBD (issue #1175).

532. ✅ **SECURITY FOLLOW-UP — THE RETENTION REFUSAL WAS ARGUMENT-BLIND ACROSS A SERVICE SEAM (item 472 follow-up, 2026-09-18).** *(Renumbered from 512 on 2026-09-19: the preceding section opened its own run at 512, and this section continues it at 526, so the entry belongs at the tail of that run. Cross-section reuse is permitted by the file's convention but is ambiguous to a reader, and nothing in the tree cited this entry by number, so the number was moved rather than the ambiguity documented.)* G-RETAIN says a `Retained[T, P]` value past P's deadline never reaches durable storage unless P declares a hold, and the flow half of that refusal followed a value only to a sink the CALLER names. A service operation's provider owns the store and the caller never names it, and the interface parameter cannot carry the qualifier that would have caught it — nothing else can cross a unit boundary, so a qualifier there is a promise the caller could not check. So `let row = load(k); let n = emit vault.stash(row)` was ADMITTED with the provider's body writing `row` to a `db`-scoped extern: the caller handed over a value that had outlived its deadline and the compiler said nothing, which is the whole of what the guarantee says cannot happen. The declaration half was never the gap — a `Retained[T, P]` parameter declared on the operation is refused by name, and the provider's body is checked against the extern's declared capability. `_Signature` now carries `persists_at` (`parameter index -> (sink, scope, via)`), the retention sibling of `reaches_sink`, populated by `_on_persistence` from the same inference walk that already computes the return taint, so the reach is INTERPROCEDURAL for free: a provider that reaches the sink through a helper fn carries the reach out too, and the refusal names the seam (`load() -> Store.stash -> db_put`) rather than only the sink. Bounded by the rules that were already true — a provider body that only receives the value admits (a reach is not a verdict), a body that only logs admits (a log is a disclosure sink, retention is about durable storage), a declared `hold:` still overrides the deadline because the hold is a property of the policy and crosses with it, and the reach is per-parameter so a value at argument 2 of a two-argument operation is refused exactly as one at argument 1. `tests/test_retention_472.py` section 1b pins all of it: four tests red before the change, four controls green either way. Scoped to G-RETAIN; the same body-walk blindness in the G-SECRET-FLOW argument direction is a different guarantee with a different rule and is sequenced separately. `src/revl/taint.py` is not a `DIGEST_INPUTS` entry, so no gate-quartet regen.
