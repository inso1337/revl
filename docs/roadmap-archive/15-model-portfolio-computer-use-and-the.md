## Model portfolio, computer-use, and the operator surfaces

521. (issue #1195) **✅ LANDED (2026-09-20 to 2026-09-25, merged `21c1cc5cd`, `657873ec0`, `e1bb81313`, `7ac39d915`): an unscoped UI verb is REFUSED BY NAME under G8, `revl audit` enumerates every reached UI emission class, an observed value flowing into an actuation is a taint refusal, the ladder rung is part of the capability token and bounded at the declaration site, and a `UiTarget` must come from a crossing that resolved it (issue #1371), per `docs/design/532-typed-computer-use.md` and pinned by `tests/test_ui_capability_namespace_521.py`. The substrate that performs an action is item 539's. TYPED COMPUTER-USE AS A HOST-BACKED EXTERN FAMILY (2026-09-19, external review).** A computer-use agent breaks the headline guarantee: its reach is "whatever the GUI permits", which is unbounded, and its inputs — a screenshot, an OCR result, a window title — are attacker-influenced. A typed `Ui` provider family (`screen.observe`, `ui.find`, `ui.click`, `ui.type`, `ui.download`) declared as a host-backed extern, deliberately NOT part of revl's core language, makes each of those an enumerable emission class: every UI target is untrusted input rather than a trusted reference, `ui.download` is a real emission with a capability rather than a side effect of a click, and an unscoped act-on-anything verb is refused rather than admitted as `*`. The open decision the item must settle is the **fallback ladder** — typed action, then a DOM selector, then a pixel-level action — and how far down it is admissible at run time under a declared policy, since an unbounded ladder is the same as no guarantee. Exit: `revl audit` over a CUA program enumerates every UI emission class it can reach, and an unscoped verb is refused. Owner: TBD (issue #1195).
    The review's reference implementation for this shape is the `trycua/cua` project, which the typed family above is a typed version of; the fallback ladder is exactly the part that project leaves open, which is why the item's open decision is the ladder rather than the verb list.
    **What makes a target "verified" is this item's real design work, and the review supplies the binding.** Every UI target is bound to the window or application identity, an accessibility-tree identity where one exists, a screenshot/DOM/AX evidence hash, the allowed action type, the user/session/task identity, a region or coordinate bound, an expiry, and whether a confirmation is required. The argument for why the binding cannot be a coordinate is the one to keep: **`(842, 611)` is not authority**, because the same pixel can mean Delete, Send or Approve after a layout change — so a coordinate is a hint that must be re-bound to a semantic target and re-verified at execution time, never a capability granted at admission. That yields the pre-execution sequence the adapter must run: the target still matches its expected identity, the window is the expected one, the action is inside the capability, the target is not classified as a sensitive control, the screen it was read from is not untrusted content, and the budget and session deadline still hold — which is why `ui.click` takes a target and not a point. The complementary refusal is that the low-level primitives stay unexposed: no single `computer.control` capability and no `mouse.move` / `mouse.click` / `keyboard.type` surface, because a semantic operation (click the button named Submit in the Billing application) is auditable and a coordinate pair is not. A recorded action carries the same binding, so the receipt for a UI step is comparable to 517's model decision: application, window, target role, target name, target evidence hash, action, capability, session. The host keeps the controls the adapter must not assume away — which desktop or VM runs, which applications are visible, which windows and targets are allowed, which keys may be generated, whether the clipboard, downloads, uploads or network are reachable, and whether a human must confirm the final action — and CUA workers run in an isolated desktop or sandbox with limited host capabilities, inheriting item 257's confinement argument rather than restating it. Recorded because 521 without the binding is a verb list, and the binding is the part the review calls the critical safety boundary.
    **THE LADDER DECISION IS SETTLED, AND ITS SHAPE IS THAT A RUNG IS PART OF THE CAPABILITY TOKEN (2026-09-20, `docs/design/532-typed-computer-use.md` §4).** A computer-use verb is an ORDINARY capability-scoped emission in a reserved, closed namespace and nothing else, so every authority surface that already reads a capability token reads a UI verb for free: the G4 subset check, the G8 audit reach, `secret K for C`, the item-246 approval gate, the `capability <glob>` policy rules, item 294's partial order, and item 249's derived sink and source classes, which read the token's dotted HEAD and therefore want exactly a reserved root. The ladder then needs no new machinery: `ui.click` is rung 0 (a semantic target), `ui.click.selector` rung 1, `ui.click.pixel` rung 2, so DESCENDING IS CROSSING A DIFFERENT DECLARED BOUNDARY RATHER THAN RETRYING THE SAME ONE. Four consequences, each already enforced on capability tokens: the admissible depth is the maximum rung over a component's declared tokens and is a compile-time fact; `revl audit` prints it with no new reporting code; the descent cannot happen inside one call, because a `ui.click` that cannot bind its target FAILS rather than becoming a `ui.click.pixel`; and the declaration must be PREFIX-CLOSED, since a component that can reach pixels but not semantic targets has no ladder, it has a pixel driver. The argument for bounding the depth is the asymmetry rather than a preference for typed APIs: rung 0 fails CLOSED (an unresolved identity is an error) while rungs 1 and 2 fail OPEN (a selector matches a different control that satisfies it, and a pixel always hits something, which is why `(842, 611)` is not authority). What revl does NOT claim is the ORDER: item 539 is right that a route condition can only check the ordering of a plan while what walks the ladder is a loop, so prefix-closure of the DECLARATION is the strongest honest form of "never inverts that order" this repository can check, and an implied ordering guarantee would be worse than no ladder. **WHAT SLICE 1 LANDED.** `src/revl/ui_family.py` holds the roots (`screen`, `ui`) and the CLOSED verb registry, each verb carrying the one sentence that says what crosses; one hook in `parser._capability_list`, the single declaration-site funnel for a capability token, raises three refusals with `code="G8"`: the root alone (`emission[ui]` names the whole GUI surface, which is not an enumerable boundary), an undeclared verb (`emission[ui.drag]`, because an invented token narrows nothing and escapes every policy rule written against the real one), and a deeper token (`emission[ui.click.pixel]`, refused until the prefix-closure check exists, since admitting a spelling ahead of the check that bounds it is the same fail-open mistake one level up). A `secret K for C` binding and a `capability <glob>` rule are SELECTORS over a token rather than statements of reach and are deliberately untouched. One deviation from the sketch above, measured rather than assumed: the verb is `ui.text`, not `ui.type`, because `type` is a reserved keyword and a dotted capability token's segments parse with `expect("ident")` at the declaration site and in `secret K for C`, so `ui.type` would be declarable but not selectable, and a floor an operator writes against it would silently select nothing. NON-VACUITY, measured on `c136eae6` with `ui_family.py` present (it is data) and the parser hook absent (it is the check): 7 of the 20 tests FAIL, 13 pass; with the hook, 20 pass. The 13 that pass on both trees are the controls, the registry assertions and the audit enumeration, and that last one is stated rather than hidden: `revl audit` already enumerates a dotted capability token, so the enumeration half of the exit needed NO new reporting code and the work was making the spelling mandatory. **WHAT REMAINS.** Slice 2 adds `screen` to `_SOURCE_CLASS_SCOPES` and `ui` to `_SINK_CLASS_SCOPES` in `src/revl/taint.py`, which is what turns `Untrusted[UiTarget]` from a convention into a G9 refusal; slice 3 admits the rung tokens and checks prefix-closure; slice 4 gives the target the binding recorded above; slice 5 the receipt. SELF-HOST: no port in slice 1, and the reason is structural rather than an exemption. `selfhost/lower.rvl`'s `admit_src` issues no admission at all (item 417), so a program carrying a reserved UI token it does not understand cannot be admitted by it. The obligation is recorded in the design doc so a later slice does not rediscover it: the first slice that decides admission on a UI token must port the check or decline the program by a NAMED marker, because the oracles catch divergence and not missing features.
