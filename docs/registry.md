# The component registry — phase 0 design

**Status:** design (2026-08-23), spec-before-code · roadmap item 49 ·
companion to [service-compat.md](service-compat.md) (the search predicate),
[queries.md](queries.md) (the envelope discipline), [holes.md](holes.md)
(fill specs as queries), and the manifest format work (roadmap item 28).

The product decision in one line: **agents import existing components
instead of regenerating them, and the whole loop costs two calls.** Every
choice below serves that line; anything that doesn't is out of phase 0.

Why this is safe *now* (the re-scoped §5 stance, roadmap item 49): the
collision argument gates publishing at scale, not reuse — the reuse loop
is search → fetch one candidate → admit, and G2 already refuses two
providers of one key at admission. Namespacing stays where item 9 put it,
gating phase 2.

---

## 1. The registry is a repository

Phase 0 has no service, no API host, no accounts. The registry is a git
repository with this layout:

```
registry/
  components/
    <name>/                    # single namespace, first-come (phase 0)
      component.rvl            # source, canonical formatting
      manifest.json            # the compiled manifest (item 28 format)
      dossier.json             # evidence: audit --json today; the item 31
                               # gauntlet dossier when it exists
      README.md                # optional, for humans
  index.json                   # GENERATED — never hand-edited
```

`index.json` maps each component to what a resolver needs without opening
sources: provided service shapes (canonicalized), required keys,
capability set, tier matrix, content hash. It is regenerated by CI from
the components, and **a stale index fails CI** — the same
regenerate-or-red discipline the conformance baselines use. "Nothing
checked it" must never read as "current".

A component enters the registry by commit (phase 0) or by `revl_publish`
(phase 1, gauntlet-gated). Either way the entry's `manifest.json` must be
byte-reproducible from its `component.rvl` by the current compiler — CI
checks that too, so an entry cannot lie about its own audit surface.

## 2. `revl_resolve` — the one search verb

MCP tool `revl_resolve` and CLI `revl resolve`, same result object
(machine first, human second — the queries.md rule).

**Request:**

```json
{
  "need":     "<service declaration source | fill-spec object | shape>",
  "manifest": { "...": "optional running composition (compiled IR)" },
  "limit":    5
}
```

- `need` accepts three forms, all reduced to one canonical service shape:
  a revl `service` declaration as source; a hole's **fill spec** (item 32)
  verbatim — a hole is a well-formed query by construction; or the shape
  object the index itself stores.
- `manifest` is optional. Without it, candidates are compatible with the
  need. **With it, candidates are additionally checked admissible against
  that running composition** (G2 provision disjointness, G3 acyclicity) —
  the answer upgrades from "compatible somewhere" to "admissible *here*".

**Matching is admission, never text.** A candidate matches iff its
provided service is §5 structurally compatible with the need — the same
`service-compat` machinery the hot-swap gate runs, pointed at the index.
No name matching, no keyword scoring, no embeddings. If the §5 check
wouldn't admit it, resolve doesn't return it.

**Response** (the queries.md envelope, verbatim discipline):

```json
{
  "ok": true,
  "query": "resolve",
  "question": "who provides a service admissible for this need?",
  "precision": "exact",
  "assumptions": [
    "index generated at <commit>; entries added since are not seen",
    "extern classifications inside candidates are trusted, not verified (G8)"
  ],
  "candidates": [
    {
      "name": "user_cache",
      "source": "<full component.rvl text>",
      "manifest": { "...": "entry's manifest.json" },
      "dossier": { "...": "present when the entry has one" },
      "why": "provides Cache: §5-compatible (params exact, returns exact)"
    }
  ]
}
```

**The two-round-trip rule is a contract, not a hope:** `source` and
`manifest` ride *inline* in the result. An agent goes need → `revl_resolve`
→ `revl_admit`/`revl_swap` in exactly two calls. Any design change that
would force a third call (a separate fetch, a pagination step, a detail
lookup) is a regression against this document.

**Ranking — least authority first.** Order candidates by:

1. smallest declared capability set (a candidate that reaches less
   outranks one that reaches more — the registry teaches the same lesson
   G4 does);
2. tighter interface fit (exact match over compatible-with-widening);
3. presence and strength of evidence (gauntlet dossier > audit-only);
4. smaller source (less for the agent to hold in context).

Popularity is deliberately **not** a rank input in phase 0: with one
author and agent traffic, download counts measure prompt fashion, not
quality. Evidence ranks; counters don't.

## 3. The reuse hint (phase 0.5) — did-you-mean for existence

When compilation/admission of a **freshly authored** component finds a
registry entry whose provided surface is §5-compatible with what was just
written, the result carries a non-blocking note:

```
note: a published component `user_cache` provides a Cache compatible with
  `MyCache` — `revl_resolve` returns it with source and manifest inline
  (REUSE-HINT; --no-reuse-hints to suppress)
```

Rules that keep the hint trustworthy:

- **Full-surface coverage only.** The hint fires when the published
  component covers the *entire* provided surface of the new one — never on
  partial overlap. Precision beats recall: one wrong hint teaches an agent
  to ignore all hints.
- **Never blocks.** It is a note on a successful result, not a rejection.
  Reuse is the path of least resistance, not a mandate — the agent (or its
  operator) may have reasons to reimplement.
- Suppressible per-call (`--no-reuse-hints`) and absent entirely when no
  index is configured.

Agents follow diagnostics more reliably than they follow instructions in
prompts. This is the mechanism that makes "import before you regenerate"
the default behavior instead of a rule every harness must remember to
state.

## 4. Security stance

- **Resolve executes nothing.** Index rows and entry sources are data. No
  candidate code runs at resolve time, no entry can carry instructions the
  resolver acts on.
- **Install is admission.** There is no separate install step to secure:
  fetched source enters a composition only through `compile_files(files,
  manifest=running)` — the same gate everything passes. The registry needs
  no trust beyond availability; a tampered entry is a candidate that fails
  the gate or visibly changes its audit surface (the manifest
  reproducibility check in §1 makes silent divergence a CI failure).
- The standing G8 caveat, restated here because it composes: an entry's
  extern classifications are trusted, not verified. The dossier *evidences*
  behavior; only the boundary enumeration is proof. `assumptions` carries
  this in every response.

## 5. Measured, not assumed

Two numbers join `bench/`, feeding the token-economy metric (item 50):

- **reuse rate** — of the specs where a compatible component exists in the
  index, how often does the agent import vs regenerate (with and without
  the hint enabled — the hint's follow-rate is its own justification);
- **token cost per path** — import (resolve + admit) vs regenerate
  (author + iterate + admit), measured on the same specs.

If agents don't reuse even when nudged, phase 1 waits and item 49 records
why.

## 6. Exit tests (phase 0)

- [ ] `revl_resolve` finds `user_cache` from a `Cache`-shaped need — by
      shape, with the source of a differently-*named* service declaration
      (proving no text matching).
- [ ] The same resolve with a `manifest` that already provides the `cache`
      key returns no candidates for it (admissible-here beats
      compatible-somewhere; G2 is the reason and the payload says so).
- [ ] A fill spec from a real hole, passed as `need` verbatim, resolves.
- [ ] A scripted agent transcript goes need → resolve → admit in exactly
      two MCP calls, source never re-sent.
- [ ] CI: hand-editing `index.json` or an entry's `manifest.json` turns
      the registry job red.
- [ ] The reuse hint fires on a full-surface-compatible fresh component,
      does not fire on partial overlap, and never changes the compile
      verdict.

## 7. Non-goals (phase 0) — declined here so they are not relitigated

Namespacing, versioning, and update flows (phase 2, gated on item 9);
hosting, accounts, tokens (phase 2); deletion/yanking policy (needs
identity first); signatures (the dossier is evidence — signing arrives
with phase 2 identity, and unsigned-but-gate-verified beats
signed-but-unverified); popularity metrics (see §2); cross-registry
federation (there is one registry until that is a problem worth having).
