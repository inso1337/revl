# Documentation staleness inventory

An inventory of every `docs/*.md` file (except this one and the roadmap): its
status and its em-dash count. The table between the `docgen` markers is
generated by `tools/docgen.py` and gated by `tools/docgen.py --check`, so it
cannot go stale; the `status` and `tier-limit notes` columns carry human
judgement and are edited by hand. The single source of truth for what has
shipped is `docs/v2.0-roadmap.md` (items marked done).

The `status` column records the last audit of each doc against the roadmap and
the code. A `needs-work` row has not been audited since it was written; that
is a statement about the audit, not a known inaccuracy.

**Status meanings**

- **stale-fixed**: audited and corrected (accuracy + em-dash/AI-tell style pass,
  verified against the roadmap's done state).
- **current**: spot-verified accurate against the roadmap or the code. The
  subject is a landed feature and the doc describes it as landed. A nonzero
  em-dash count still means a style pass is pending.
- **live-owned (not audited)**: actively maintained alongside the code
  (self-host and bench docs), so it is not audited as a snapshot.
- **needs-work**: not deep-audited. Accuracy not individually confirmed, and the
  em-dash/AI-tell style pass is still pending. Not known to be wrong, just not
  yet checked. Sorting by em-dash count is a reasonable order for a follow-up.

**Columns**

- **em-dashes**: count of the em-dash character remaining (0 = style-clean;
  em-dashes inside ` ```revl ` fences are intentionally preserved).
- **tier-limit notes**: `yes` = the doc contains a genuine "not yet lowerable /
  not yet wired" tier limitation worth confirming against current tier support
  before it is trusted (usually accurate, but the first thing to re-check).

**Naming convention (item 255).** The dogfood workload is named uniformly as
**the lighthouse workload** across `docs/` and `dogfood/`. Public text does not
carry absolute local paths or the workload's internal milestone numbers; a
findings file cites its own finding id, not the workload's build scaffolding.
Item 248 is the single anchor entry for the workload in `docs/v2.0-roadmap.md`.
Forward rule: new text uses the lighthouse-workload framing only.

The table below is GENERATED. `doc` and `em-dashes` come from the tree
(`docs/*.md`, and each file's em-dash count); `status` and `tier-limit
notes` are human judgement and are carried across a regeneration. Run
`make docs-gen` after editing any doc, or `tools/docgen.py --check` reds CI.
A hand-corrected inventory drifts back within a day, which is why this one is
regenerated rather than edited.
