# `revl import wit` — a WIT world becomes a revl service

**Status:** implemented (`src/revl/import_wit.py`, `tests/test_import_wit.py`) ·
roadmap item §4, the second member of the import codegen family after
`revl mcp import` (docs/mcp-bridge.md) · companion to docs/interop-bridge.md

```
revl import wit <file.wit> [--backend wasm|ts|py|rust] [--pure NAME]... [-o out.rvl]
```

It reads one `.wit` file and prints revl source: a `service` per WIT
interface, revl `type` declarations for the WIT data types, an `extern` per
operation, and a provider component wiring the two together. The output is
meant to compile as-is — every fixture in the test suite is round-tripped
through `compile_files` and its IR inspected — and then to be edited in
exactly one place: the host bodies.

```console
$ revl import wit tests/fixtures/wit/greeter.wit
```

```revl
// Generated by `revl import wit` — do not edit by hand.
// Source WIT: tests/fixtures/wit/greeter.wit
// WIT package: example:greeter@1.0.0
// ...
service Greeter {
  // Build a greeting for a name. Computes a string and nothing else.
  // plain by assertion: `/// @revl:pure` in …/greeter.wit — WIT itself makes no such claim
  fn greet(name: Str) -> Str
  // Append the greeting to the host's log. Nothing here can be undone.
  // WIT carries no reversibility claim: `emission` by default (G8)
  emission fn log_greeting(name: Str, at_millis: Int)
}

extern pure fn wit_greeter_greet(name: Str) -> Str
  = @wasm { ;; call the WIT export example:greeter@1.0.0/greeter#greet here }

extern emission fn wit_greeter_log_greeting(name: Str, at_millis: Int)
  = @wasm { ;; call the WIT export example:greeter@1.0.0/greeter#log-greeting here }

component GreeterProvider provides greeter: Greeter {
  provide greeter {
    fn greet(name) = wit_greeter_greet(name)
    fn log_greeting(name, at_millis) = wit_greeter_log_greeting(name, at_millis)
  }
}
```

---

## 1. The emission question — the only interesting decision here

Everything else in this importer is transcription. This part is a judgement,
so it is stated rather than buried.

revl distinguishes a plain `fn` (revertible by declaration) from an
`emission fn` (crosses the system boundary irreversibly). A service
declaration is an **upper bound** on every provider of that service (G4
emission propagation): an operation declared plain may never reach an
irreversible effect, in *any* provider, ever — the compiler refuses the
provider otherwise. That is what makes a consumer's G8 audit meaningful, and
it is exactly why an under-declared imported operation is not a cosmetic
error: it silently weakens every downstream audit.

**WIT carries no such information.** A WIT world describes shape — names,
parameters, results. `read: func() -> string` and `delete-everything: func()`
are indistinguishable to it.

So this importer takes the trust direction `revl mcp import` already
established, where only an explicit `readOnlyHint: true` avoids `emission`:

> **Every imported operation is `emission` unless something explicitly and
> positively asserts otherwise.**

Two things can make that assertion, and both are *human claims that the
compiler cannot verify*, so both are recorded in the generated source next to
the operation they weakened:

| Assertion | Who is claiming it | MCP analogue |
|---|---|---|
| `/// @revl:pure` on the WIT function | the interface's author | `readOnlyHint: true` in the tool manifest |
| `--pure <interface>.<func>` (or `--pure <func>`) at import time | the importing engineer | — (a `revl import wit` addition) |

A `--pure` name that matches no function in the WIT is an **error**, not a
no-op. Leaving it `emission` would be safe, but the engineer would believe
they had narrowed something.

### Why the weakened form is still sound

An asserted-pure operation is emitted as a plain `fn` backed by an
`extern pure fn`; everything else is `emission fn` backed by an
`extern emission fn`. The pairing is not a convention this generator promises
to keep — the compiler enforces it. Flip one generated extern to `emission`
and leave the operation plain, and compilation fails:

```
`Probe.read_only_looking` is declared plain, but this implementation reaches
`wit_probe_read_only_looking()`
  a service declaration bounds what its providers may do — mark it
  `emission fn read_only_looking(...)` in service `Probe`, or move the
  irreversible call out of this method (G4)
```

(`tests/test_import_wit.py::test_a_plain_operation_backed_by_an_emission_is_rejected`.)
So a generated plain `fn` is genuinely plain: the language, not the importer,
is the thing being trusted.

An operation asserted pure whose implementation *does* write something is
still a lie — but it is a lie with a name, a line, and an author attached, in
the generated source, on the audit surface. That is the most this boundary
can offer.

## 2. Type mapping

| WIT | revl | note |
|---|---|---|
| `string` | `Str` | |
| `char` | `Str` | revl has no character type; widening, so inbound is safe and outbound needs the host to validate |
| `bool` | `Bool` | |
| `s8` `s16` `s32` `s64` | `Int` | |
| `u8` `u16` `u32` `u64` | `Int` | **lossy**: a `u64` above 2^63−1 does not survive the trip |
| `f32` `f64` (and `float32`/`float64`) | `Float` | |
| `list<T>` | `List[T]` | including `list<u8>` — mapped to `List[Int]`, not `Bytes`, so the table stays one-to-one |
| `option<T>` | `Opt[T]` | `option<option<T>>` is **refused**: `Opt` does not nest, and `Opt[Opt[T]]` cannot tell the two absences apart |
| `result<T, E>` | `Result[T, E]` | `result<_, E>` → `Result[Unit, E]`, `result<T>` → `Result[T, Unit]`, bare `result` → `Result[Unit, Unit]` |
| `record r { … }` | `type R = { … }` | fields kebab → snake |
| `variant v { a(t), b }` | `type V = A(T) \| B` | |
| `enum e { a, b }` | `type E = A \| B` | a payload-free ADT |
| `type x = <t>;` | *inlined at use sites* | see below |
| `resource r { … }` | `type R = { handle: Int }` + `extern acquire fn r_new(…) -> R undo r_drop(result)` (with `extern emission fn r_drop(self: R)` declared alongside) + methods as `r_m(self: R, …)` | a live handle onto revl's acquire-returned-handle model; `result` is the undo slot's implicit binding — the acquired handle; see docs/wit-bridge.md §3 |
| `borrow<r>`, `own<r>` | the handle type `R` | a resource *reference*; copy-vs-move is tracked by the acquire/undo pair |
| `interface i { … }` | `service I` + `extern`s + `component IProvider provides i: I` | |
| `world w { export f: func(…) }` | `service W` + provider | a world export is what a revl consumer may call |
| `world w { import f: func(…) }` | `service WImports`, **declaration only** | a world import is what the component expects to be *given*; revl code provides it, so no extern is invented |
| `world w { export some-iface; }` | a note in the header | the interface itself is generated from its own definition |

Names cross conventions: WIT kebab-case types and variant cases become
PascalCase (`in-stock` → `InStock`), functions, parameters and record fields
become snake_case (`log-greeting` → `log_greeting`). A name that would collide
with a revl keyword gains a trailing underscore (`%type` → `type_`); a type
name that would shadow a revl built-in is suffixed (`%result` → `ResultTy`).
Every rename is reported as a `// note:` in the generated header — a silent
rename is a trap for whoever reads the output. A variant case that lands on
`Ok`, `Err`, `Some` or `None` is *not* renamed (it is a legal revl case name)
but is reported the same way, because it shadows the built-in constructor
inside the generated module.

WIT's `%` escape is honoured: `%result` names a user type rather than WIT's
built-in `result`, and `%type: func(...)` is an operation, not a type
definition.

### Why aliases are inlined rather than declared

`type sku = string;` does **not** become `type Sku = Str`. In revl,
`type X = Y` declares a single-case *variant* named `Y` — an ADT, not an
alias (docs/syntax-2.0.md §2; revl has no alias form). Emitting it would
compile and mean something entirely different. The importer therefore
resolves aliases at their use sites, and records what it did:

```
// note: WIT `type sku = ...` is inlined as `Str` (revl has no type alias:
// `type X = Y` would declare a variant)
```

Alias cycles are reported as cycles rather than recursed into.

## 3. What it refuses, and why

The rule is: **refuse rather than emit something wrong.** Each refusal names
the construct, the line it appeared on, and the way forward.

> **`resource`, `borrow<T>` and `own<T>` are no longer refused** — they map
> onto revl's acquire-returned-handle model. See docs/wit-bridge.md §3.

| Refused | Why | What to do instead |
|---|---|---|
| `stream<T>` | an open-ended effect, not a value | model it as a service whose operations are `emission` |
| `future<T>`, `f: async func(...)` | revl spells asynchrony as `async fn` on a service operation | declare that operation by hand |
| `flags` | revl has no bit-set type | a `record` of `bool`s, or a `list<enum>` |
| `tuple<...>` | revl has no tuple type | declare a WIT `record` with named fields |
| a `func` type as a value (a callback) | no host-crossing function values | invert the callback into a service the host requires |
| named/multiple results `-> (a: u32, b: u32)` | revl operations return one value | return a `record` |
| an inline `interface { … }` inside a world | keeps the resolver to one shape | lift it to a top-level `interface` and reference it by name |
| `include` in a world, `use` from another package, nested `package { }` blocks | all need a multi-package resolver; this importer reads exactly one file | copy the definitions in, or import the other package separately |
| two definitions of one type name with different shapes | revl types share one module namespace, so they would collide | rename one in the WIT |
| two items generating one service name | same namespace argument | rename one in the WIT |
| `option<option<T>>` | `Opt[Opt[T]]` cannot distinguish the two absences | declare a `variant` naming both cases |

The WASI worlds built around handles (`wasi:filesystem`, `wasi:sockets`) now
import, because their central abstraction — a resource, a handle with identity
— is exactly revl's acquire-returned resource type: a value an `extern acquire`
returns, whose lifetime is a tracked inverse (`undo`) and which crosses a seam
by proxy, not by copy (`src/revl/distribute.py`). The mapping and its
round-trip are documented in docs/wit-bridge.md §3.

## 4. `--backend`, and one thing the roadmap assumed

The generated `extern` bodies are **stubs** — the typed boundary is
generated, the host call is not — and `--backend` chooses which tier they are
tagged for. `--backend wasm` (the default) matches where a WIT world lives;
`ts`, `py` and `rust` target the hosted tiers.

The roadmap's §4 premise was that "the wasm tier's types line up one-to-one
with WIT worlds, so it is codegen rather than design". The *types* do line up
one-to-one — that is section 2 above, and it went through without a
negotiation, and the round trip back down to wasm closes as well. The
cordis-wasm tier carries `Int` as an **i64**, and `Str`, `Bytes`, lists,
records, variants, `Opt` and `Result` cross its service boundary as
canonical-ABI pointers into linear memory. What it refuses is **`Float`,
`Map` and declared function types**, and nothing else
(`backends/wasm/emit.py`, `_V3Emitter._check_type`, whose refusal reads "type
'Float' is not lowerable — this tier supports
Int/Bool/Str/Bytes/List/record/variant/Opt/Result values", with a separate
message for a declared function type). WIT `f32`/`f64` map to `Float`, so a
world reaching for a float is the remaining gap; a world of strings, records
and lists imports *and* emits. With `--backend py`,
`tests/fixtures/wit/catalog.wit` goes all the way to a cordis-py module
instead.

So the import is codegen, as predicted.

### The component edge is a second, narrower boundary

Do not read `_check_type`'s refusal as the only one. Presenting a component
over the **canonical ABI** (`backends/wasm/canonical.py`, `emit_component`,
the thing `build_component` wraps into a real component binary) is a separate
surface with its own, *narrower* gate: `_Canon.can_lower_param` and
`can_lower_result` carry `Int`, `Bool`, `Str`, lists, records and
variants/`Opt`/`Result`. A method whose whole signature is not lowerable
*there* is left off the exported WIT interface and stays a core-module export
for intra-module calls, never mis-lowered; `emit_component` raises only when
no method crosses at all.

Two differences from the service-type check, spelled out because conflating
the two surfaces is how a reader ends up blaming the wrong construct:

- **`Bytes` lowers at the service boundary but does not cross the component
  edge**, and neither does a variant *parameter* whose payload is itself an
  aggregate (the same variant is fine as a *result*, which crosses through
  memory).
- **A resource handle is not refused at either surface.** `canonical.py`'s
  prose and its two `EmitError` messages name "a resource handle" among the
  things it cannot lower, and that is about a WIT-native `own<r>`/`borrow<r>`
  handle. Nothing this importer generates is one: a WIT `resource` imports as
  `type Descriptor = { handle: Int }` (section 3), a record of `Int`, and the
  IR type table has no resource kind at all — only `record` and `variant`.
  `tests/fixtures/wit/resource.wit` imports on `--backend wasm` and the wasm
  emitter lowers it.

## 6. The rest of the family

`revl import openapi` is the remaining roadmap item. The emission question
answers itself more easily there — HTTP verbs carry a weak but real
reversibility signal (`GET`/`HEAD` are nominally safe) — but the same rule
should hold: an explicit, positive, *recorded* claim to weaken the default,
never an inference the generated source does not state.
