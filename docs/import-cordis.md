# `revl import cordis` — a Cordis plugin becomes a revl service

**Status:** implemented (`src/revl/import_cordis.py`,
`tests/test_import_cordis.py`) · roadmap item §14, the fourth member of the
import codegen family after `revl mcp import` (docs/mcp-bridge.md),
`revl import wit` (docs/import-wit.md) and `revl import openapi`
(docs/import-openapi.md).

```
revl import cordis <plugin.ts> [--service NAME] [--pure OP]... [--mark-unrecovered] [--backend ts|py|rust] [-o out.rvl]
```

It reads one Cordis plugin's `inject`/`provide` surface and prints revl
source: a `service` for the service the plugin provides, an `extern` per
operation, and a provider component wiring the two together — so a revl
composition can inject a real Cordis / DeepSeek-Harness plugin as a coeffect.
The output is meant to compile as-is (every fixture in the test suite is
round-tripped through `compile_source`) and then to be edited in exactly one
place: the extern host bodies.

```console
$ revl import cordis tests/fixtures/cordis/cache.ts
```

```revl
// Generated by `revl import cordis` — do not edit by hand.
// Source plugin: tests/fixtures/cordis/cache.ts
// Cordis plugin: cache
// Service surface: class Cache extends Service
// ...
service Store {
  // Read a cached value. Pure lookup — reads the map and nothing else.
  // plain by assertion: `@revl:pure` in …/cache.ts — the plugin's TypeScript makes no such claim
  fn get(key: Str) -> Opt[Str]
  // Overwrite the log-through cache for `key`. Writes through to `database`.
  // untyped TS carries no reversibility claim: `emission` by default (G8)
  emission fn set(key: Str, value: Str)
}

extern pure fn cordis_store_get(key: Str) -> Opt[Str]
  = @ts { // call the Cordis service method `store.get` here }

extern emission fn cordis_store_set(key: Str, value: Str)
  = @ts { // call the Cordis service method `store.set` here }

component StoreProvider provides store: Store {
  provide store {
    fn get(key) = cordis_store_get(key)
    fn set(key, value) = cordis_store_set(key, value)
  }
}
```

---

## 1. Why this member is different from WIT and OpenAPI

WIT and OpenAPI wrap **specified** interfaces: a WIT `func` has a signature, an
OpenAPI operation has a JSON schema. The importer *transcribes* what the spec
already states. A Cordis plugin has no such spec — it is **untyped
TypeScript**, and its service surface is whatever methods a
`class … extends Service` (or a `ctx.provide(…)` object literal) happens to
expose, typed however much the author bothered to annotate.

So the work here is not transcription, it is **recovery** — reading a
signature back out of the source — and, more importantly, saying so loudly
where a signature **cannot** be recovered. The family's rule ("nothing checked
must never read as clean") applies to interfaces too: a fabricated signature is
worse than an admitted gap.

## 2. The emission question — the family's rule, verbatim

revl distinguishes a plain `fn` (revertible by declaration) from an
`emission fn` (crosses the system boundary irreversibly). A service
declaration is an **upper bound** on every provider of that service (G4
emission propagation): an operation declared plain may never reach an
irreversible effect, in *any* provider, ever — the compiler refuses the
provider otherwise. An under-declared imported operation therefore silently
weakens every downstream G8 audit.

A Cordis plugin vouches for nothing about reversibility. So this importer takes
the same trust direction the whole family takes:

> **Every imported operation is `emission` unless something explicitly and
> positively asserts otherwise.**

Two things can make that assertion, and both are *human claims the compiler
cannot verify*, so both are recorded in the generated source next to the
operation they weakened:

| Assertion | Who is claiming it | Analogue |
|---|---|---|
| `@revl:pure` in a method's JSDoc | the plugin's author | WIT's `/// @revl:pure`, MCP's `readOnlyHint: true` |
| `--pure <Service>.<method>` (or `--pure <method>`) at import time | the importing engineer | `revl import wit --pure` |

A `--pure` name that matches no method is an **error**, not a no-op — leaving
it `emission` would be safe, but the engineer would believe they had narrowed
something.

### Why the weakened form is still sound

A pure-asserted operation is emitted as a plain `fn` backed by an
`extern pure fn`; everything else is `emission fn` backed by an
`extern emission fn`. The pairing is enforced by the *compiler*, not promised
by this generator: flip one generated extern to `emission` and leave the
operation plain, and compilation fails
(`test_a_plain_op_backed_by_emission_is_rejected`). So a generated plain `fn`
is genuinely plain — the language, not the importer, is the thing being
trusted.

## 3. What is recovered

| Evidence | Recovered from |
|---|---|
| plugin **name** | `export const name = '…'`, or a plugin object's `name:` field, else the filename |
| **inject** (coeffect dependencies) | `export const inject = ['a', 'b']`, or `inject: { required: [...], optional: [...] }` — surfaced in the header (see §5) |
| the provided **service key** | `export const provide`, a plugin object's `provide:` field, a `Service` subclass's `super(ctx, 'key')` or `static provide`, or `ctx.provide('key')` |
| the **method surface** | the public methods of a `class … extends Service`, or of a `ctx.<key> = { … }` object literal |
| parameter / return **types** | TypeScript annotations, or JSDoc `@param {T}` / `@returns {T}` |
| **named record types** | an `interface`, a `type X = { … }` alias, or a plain data `class` — defined in the plugin file *or* followed through a **local** import — transcribed as a revl record `type` (see below) |
| method **descriptions** | the prose lines of a method's JSDoc (copied as `//` comments) |

The method surface is recovered through the **real base chain**, so a `Service`
subclass reached via a project-local base — `class Sessions extends BaseStore`
where `BaseStore extends Service`, or a base imported under an alias — is
recovered, not just a literal `extends Service`; public methods inherited from a
local base class are merged in (the derived class wins on a name collision). A
method carrying **decorators** (`@cache`, `@throttle(100)`, `@audit.log`, …) is
recovered too: the decorators are skipped to reach the underlying signature, and
a `@revl:pure` JSDoc above them still applies.

A **nominal parameter/return type** that names a record is no longer refused
outright: the importer follows the plugin's own **local** imports (relative
`./…` paths) to the definition, transcribes it — and any record it nests, in
whatever further local module — as a revl `type` emitted ahead of the service
(dependency-first, so the file compiles as-is), and references it by name. A
bare `type X = string` alias resolves inline (revl has no type alias). A nominal
type that is *not* reachable through a local import — a bare undefined name, or
one imported from a *package* — is still refused (§4).

### Type mapping (TypeScript → revl)

| TypeScript | revl | note |
|---|---|---|
| `string` | `Str` | |
| `number` | `Float` | TS has one numeric type; revl splits `Int`/`Float`, and `Float` is the safe superset. Use `bigint` in the plugin to recover an `Int` |
| `bigint` | `Int` | the one unambiguously integral TS spelling |
| `boolean` | `Bool` | |
| `Uint8Array` / `Buffer` / `ArrayBuffer` | `Bytes` | |
| `T[]` / `Array<T>` / `ReadonlyArray<T>` | `List[T]` | |
| `Record<K, V>` | `Map[K, V]` | |
| `T \| null` / `T \| undefined` | `Opt[T]` | any *wider* union is refused (§4) |
| `Promise<T>` | `T` | not a revl `async fn`: that keyword governs `await` boundaries in the *provider*, and this provider only forwards to an extern. The asynchrony lives inside the host body, which resolves the Promise before returning `T` (recorded as a `// note:`) |
| `void` / `undefined` / `never` return | *(no result)* | |
| a string / numeric literal type | `Str` / `Int` | |
| a named `interface` / `type … = { … }` / data `class` | a revl record `type` | followed in the plugin file or a *local* import, and emitted ahead of the service; fields cross camelCase → snake_case, an optional field becomes `Opt[T]` (§3) |

Names cross conventions: a plugin's camelCase methods, parameters and the
provide key become snake_case (`readOnlyLooking` → `read_only_looking`); the
service is PascalCase of the provide key. A key that would name a revl built-in
type (`list`, `result`, …) gains a `Service` suffix (`list` → `ListService`),
and every rename is reported as a `// note:` in the header.

Cordis / `Service` lifecycle hooks (`start`, `stop`, `dispose`, `fork`) are
**not** part of the callable surface: they are detected as teardown evidence
(§5) and left out of the generated service.

## 4. What is refused — rather than guessed

The rule is the family's: **refuse rather than emit something wrong.** Each
refusal names the construct, its line, and the way forward.

| Refused | Why | What to do |
|---|---|---|
| a parameter with **no** TS type and no JSDoc type | there is nothing to recover; a guessed `Str` would be a fabricated contract | annotate the parameter, or `--mark-unrecovered` (§4.1) |
| `any` / `unknown` / `object` / `Function` / `symbol` | TypeScript's untyped escape hatches — no honest revl spelling | give the method a real type |
| an inline object / tuple type `{ a: string }` | revl records are *nominal* | declare a named type and annotate with it |
| a **nominal** type with no record definition in this file or a local import (`UserRecord`) | there is no definition to stand behind the name (a *local* record is followed and transcribed instead — see §3) | declare its revl `type` by hand and reference it, or make it an `interface` / `type` in a local module |
| a union of several concrete types (`A \| B`) | a sum type with no tag has no revl spelling | declare a named `variant` |
| a generic other than `Array` / `Promise` / `Record` | not mapped | reshape it, or wrap by hand |
| a plugin with **no** recoverable provided service | nothing to wrap | expose one of the `provide` forms in §3, or pass `--service` |
| a provided service with **no** readable method surface (a dynamically-built object) | it cannot be read statically | declare its `service` by hand |
| a service whose **every** operation is unrecoverable | nothing callable remains to generate | annotate the plugin and re-import |

### 4.1 `--mark-unrecovered`: a loud gap instead of a hard stop

By default an unrecoverable signature stops the import. With
`--mark-unrecovered`, the recoverable surface is still generated and each
unrecoverable method is replaced by a `// UNRECOVERED` marker — a comment, so
the file still compiles, but one that reads as unmistakably incomplete and
never emits a guessed signature:

```revl
service Registry {
  // Look up a plugin's version string.
  // untyped TS carries no reversibility claim: `emission` by default (G8)
  emission fn version(id: Str) -> Str
  // UNRECOVERED: Registry.install — parameter `spec` has no TypeScript type …
  //   TS type `none` at …/mixed.ts:19; annotate the plugin and re-import.
  //   fn install(...)  // signature not emitted: it would have to be guessed
}
```

The same `// UNRECOVERED:` line is echoed in the header, so a reader who only
skims the top of the file still sees that the surface is partial.

## 5. Injects and teardown — surfaced, never faked

Two things a Cordis plugin carries have no faithful automatic translation, and
the importer is deliberately honest about both rather than inventing one:

**The plugin's own `inject`** (its coeffect dependencies) is what the plugin
needs from *its* Cordis runtime. The revl composition consuming the generated
service must satisfy those on the Cordis side, but their *interfaces* are not
in this file, so the importer surfaces them in the header rather than
fabricating `inject … : SomeService` clauses that could not compile:

```
// The plugin's own coeffect dependencies (its `inject`), which the
// revl composition consuming this service must satisfy on the Cordis
// side — surfaced, not wired (their interfaces are not in this file):
//   required: database
//   optional: logger
```

**Teardown** (`ctx.on('dispose', …)`, `ctx.effect(…)`, `[Symbol.dispose]`, a
`Service.stop()`) is the undo/`acquire` semantics the roadmap calls out as the
genuinely hard recovery. Recovering *which operation* an acquired resource
belongs to, and what its inverse is, cannot be done from untyped TS — so the
importer **will not fake it**. It detects the teardown, reports it with its
line, and points at the hand-written form:

```
// Teardown detected but NOT paired to any operation — recovering undo
// semantics from untyped TS is exactly what this importer will not
// fake. If an operation acquires a resource, wrap it by hand as
// `extern acquire fn ... undo ...` so its release is a tracked inverse (G4):
//   stop() teardown at …/cache.ts:43
```

That is the honest outcome: an `acquire`/`undo` pair is a G4 obligation with a
tracked inverse, and a generated approximation would be worse than a
hand-written one.

## 6. `--backend`

The generated `extern` bodies are **stubs** — the typed boundary is generated,
the host call into the Cordis service is not — and `--backend` chooses which
tier they are tagged for: `ts` (the default, where a Cordis plugin lives),
`py`, or `rust`. There is deliberately no `wasm`: the cordis-wasm tier is
i32-only, so it cannot host a TypeScript plugin.

## 8. The family, complete

`revl import cordis` is the fourth member the roadmap's §4 family grew to. The
emission rule is identical across all four; what changes is where the
reversibility evidence lives (nowhere in WIT, in the HTTP verb for OpenAPI, in
an MCP `readOnlyHint`, and — here — only in a JSDoc `@revl:pure` or the
engineer's `--pure`), and how much of the *signature itself* has to be
recovered rather than read. Cordis is the extreme of that axis: it is the one
member where the importer must reconstruct the types before it can even ask the
emission question, and the one where "say so loudly" applies to the signature,
not just the classification.
