# `revl import openapi` — an HTTP API becomes a revl service

**Status:** implemented (`src/revl/import_openapi.py`,
`tests/test_import_openapi.py`) · roadmap item §4, the third and last member of
the import codegen family after `revl mcp import` (docs/mcp-bridge.md) and
`revl import wit` (docs/import-wit.md)

```
revl import openapi <spec.json> [--backend ts|py|rust] [--service NAME]
                                [--pure OP]... [--emission OP]... [-o out.rvl]
```

It reads one OpenAPI 3.x document and prints revl source: a revl `type` for
every schema it meets, one `service` for the API, an `extern` per operation,
and a provider component wiring the two together. The output is meant to
compile as-is — every fixture in the test suite is round-tripped through
`compile_files` and its IR inspected — and then to be edited in exactly one
place: the host bodies.

```console
$ revl import openapi tests/fixtures/openapi/heartbeat.json
```

```revl
// Generated by `revl import openapi` — do not edit by hand.
// Source document: tests/fixtures/openapi/heartbeat.json
// OpenAPI: 3.0.3
// API: Heartbeat 1.0.0
// Server: https://probe.example.com
// ...
type GetStatusResponse = { ok: Bool, checked_at: Str, detail: Opt[Str] }

service Heartbeat {
  // GET /status — Report the current status. Reads a cached value.
  // `GET` is safe by RFC 9110 §9.2.1: the API author's claim about their server, not a property this compiler checked
  fn get_status() -> GetStatusResponse
  // POST /status — Force a fresh check. Enqueues work on the server.
  // `POST` is not safe by specification: `emission` (G8)
  emission fn post_status()
}

extern pure fn http_heartbeat_get_status() -> GetStatusResponse
  = @ts { // GET https://probe.example.com/status — send the request and decode the JSON response here }

extern emission fn http_heartbeat_post_status()
  = @ts { // POST https://probe.example.com/status — send the request and decode the JSON response here }

component HeartbeatProvider provides heartbeat: Heartbeat {
  provide heartbeat {
    fn get_status() = http_heartbeat_get_status()
    fn post_status() = http_heartbeat_post_status()
  }
}
```

## 1. The emission question — and here there is real evidence

This is the one judgement in the importer, so it is stated rather than buried.

revl distinguishes a plain `fn` (revertible by declaration) from an
`emission fn` (crosses the system boundary irreversibly). A service
declaration is an **upper bound** on every provider of that service (G4
emission propagation): an operation declared plain may never reach an
irreversible effect, in *any* provider, ever. That is what makes a consumer's
G8 audit meaningful, and it is why an under-declared imported operation is not
cosmetic — it silently weakens every downstream audit.

`revl import wit` classifies *everything* `emission`, because a WIT world says
nothing about reversibility: `read: func() -> string` and
`delete-everything: func()` are indistinguishable to it. **OpenAPI is the
first member of the family where the document itself carries the signal.**
RFC 9110 §9.2.1 defines `GET`, `HEAD`, `OPTIONS` and `TRACE` as **safe** —
"essentially read-only" — and an author who writes `get:` is adopting that
contract for that operation. That is an explicit, positive, in-band claim,
which is exactly what the family's rule asks for before weakening the default.
So:

> **Every imported operation is `emission` unless the HTTP method is safe by
> specification, or a recorded human claim says otherwise.**

Three things about that sentence matter enough that the generated header
states all three, next to the operations they govern:

**Safe-by-spec is a claim, not a proof.** It is the API author asserting
something about their server, and this compiler cannot check it. `GET /logout`
is legal HTTP. So is a `GET` that writes an audit row, a `GET` whose query
parameters enqueue a job, a `GET` that mints a session cookie. None of them
are visible in the document. The generated source therefore says *whose* claim
each plain `fn` rests on, in the same way `revl import wit` records a
`--pure`. Read the implementation before trusting one.

**Safe is not idempotent, and idempotent is not reversible.** `PUT` and
`DELETE` are idempotent by specification and are still `emission` here.
Idempotence says a repeat is harmless; it says nothing about undoing the
first call, which is what G4 is about. Reading "idempotent" as "revertible" is
the most tempting wrong inference available at this boundary, so the header
names it.

**Idempotency rides along as a delivery claim, not a proof.** Since RFC 9110
§9.2.2 defines `PUT` and `DELETE` as idempotent, the importer writes
`emission idempotent fn` for them — the checked IR property that earns the
runtime its auto-retry right (docs/delivery-semantics.md, roadmap item 44).
It is the same claim-shaped evidence as `safe`: the spec's word about the
author's server, not a proof this compiler checked. `POST` and `PATCH` are
not idempotent by specification and stay a bare `emission fn`.

**revl's `pure` and HTTP's `safe` line up on the axis revl cares about.**
`pure` in revl means "no observable effect" (docs/syntax-2.0.md §6). It does
*not* mean deterministic — and a `GET` is certainly not deterministic, since
the resource changes underneath it. That is fine: an `extern pure fn` wrapping
a `GET` is claiming the call leaves nothing behind, not that it returns the
same answer twice.

### Overriding, in both directions

| Override | Who is claiming it | Effect |
|---|---|---|
| `x-revl-emission: true` on the operation | the API author | a safe verb becomes `emission` |
| `--emission <op>` at import time | the importing engineer | same |
| `x-revl-emission: false` on the operation | the API author | an unsafe verb becomes plain |
| `--pure <op>` at import time | the importing engineer | same |

An operation can be named three ways: by its generated revl name
(`get_pets_by_id`), by its `operationId`, or by `"GET /pets/{id}"`. An
override that matches nothing is an **error**, not a no-op — silently leaving
an operation classified by its verb when the engineer believes they changed it
is the failure this whole boundary is trying to avoid.

**An explicit emission claim beats an explicit pure claim, from any source.**
Strengthening takes one voice; weakening takes unanimity. That is the only
asymmetry, and it points the way G4 points.

Both `x-revl-emission: true` (a real read that writes an access log) and
`--pure` (the `POST /search` whose body is just a large query) appear in
`tests/fixtures/openapi/petstore.json`, and every override is echoed into the
generated source beside the operation it changed.

### Why the weakened form is still sound

A plain operation is emitted as a plain `fn` backed by an `extern pure fn`;
everything else is `emission fn` backed by `extern emission fn`. The pairing
is not a convention this generator promises to keep — the compiler enforces
it. Flip one generated extern to `emission` and leave the operation plain, and
compilation fails:

```
`Probe.get_thing` is declared plain, but this implementation reaches
`http_probe_get_thing()`
  a service declaration bounds what its providers may do — mark it
  `emission fn get_thing(...)` in service `Probe`, or move the irreversible
  call out of this method (G4)
```

(`tests/test_import_openapi.py::test_a_plain_operation_backed_by_an_emission_is_rejected`.)
So a generated plain `fn` is genuinely plain: the language, not the importer,
is the thing being trusted. A `GET` that actually writes is still a lie — but
it is a lie with a verb, a path and an author attached, in the generated
source, on the audit surface. That is the most this boundary can offer.

### The third claim: compensate-grade reversals (item 254)

`safe` and `idempotent` are claims the RFC makes about a verb. A third claim
sits on top of them, is narrower than either, and is never made by a verb alone:
that an emission has a **documented reversal** an abort can issue.

Mark the operation `x-revl-compensate: true` and name the route it takes, and
the generated extern carries a `compensate` slot: a best-effort reversal fired
at teardown on abort.

```yaml
# PUT: restore the preimage
put:
  operationId: setConfig
  x-revl-compensate: true
  x-revl-preimage: getConfig      # the safe GET whose response is put back
  x-revl-if-match: true           # the endpoint exposes an ETag / version token

# DELETE: recreate from the preimage, through the documented create
delete:
  operationId: deleteConfig
  x-revl-compensate: true
  x-revl-preimage: getConfig      # read BEFORE the delete
  x-revl-undo: createConfig       # the create the reversal re-sends it through

# POST: delete what it created, addressed by a response field
post:
  operationId: createConfig
  x-revl-compensate: true
  x-revl-undo: deleteConfig       # the documented delete
  x-revl-undo-key: id             # a REQUIRED field of the POST's response
```

The engineer equivalents are `--compensate OP`, `--preimage OP=GETOP`,
`--undo OP=UNDOOP`, `--undo-key OP=FIELD` and `--if-match OP`, on the same
footing as `--pure`/`--emission`.

**What it is, exactly.** Compensate-grade, and that is the ceiling. The reversal
lands on the **audit** surface, never a proof surface: it makes no
`noResidue`/witness claim, restores **server state** only, and is best-effort —
it may 5xx or time out. Reversal is not un-observation, and over a network that
is the common case rather than the edge: a rewound `PUT` does not unsend what a
webhook subscriber already saw, and deleting a created resource does not undo
the email that creating it sent. Both sentences are in the generated source, on
the operation. The reversal is itself an outbound crossing on the
`net.<host>` cap, enumerated at teardown as its own event.

**What it refuses.** Each verb takes one route shape, and a route with a leg
missing is a hard error rather than a compensation that fires at the wrong
resource:

| verb | route | needs |
| --- | --- | --- |
| `PUT` | `restore` | a safe `GET` preimage; the undo defaults to the `PUT` |
| `DELETE` | `recreate` | a safe `GET` preimage **and** a create that can carry it |
| `POST` | `delete-created` | a `DELETE` undo **and** a required response key |
| `PATCH` | — | refused: a partial merge has no inverse a document can name |

Three refusals are worth calling out, because each is a place where a
compensation would otherwise look fine and do the wrong thing:

* a `DELETE` whose recreate cannot **carry** the preimage — the create's request
  body type must be the preimage's response type. A create that cannot hold a
  field the original had restores a *different* resource;
* a `POST` that cannot **name** what it created — no response body, a key that
  is not a required non-nullable field, a non-record response, or a delete
  needing more inputs than the one key. An unkeyed compensation is refused, not
  guessed at;
* an undo wired to the wrong verb. That is not a weaker reversal, it is a second
  forward effect wearing a reversal's name.

**Concurrency.** Where the endpoint exposes a version token, `x-revl-if-match:
true` makes the reversal issue under `If-Match` (`If-None-Match: *` for a
recreate, which is a create) and fail loudly on a racing writer. Without one it
is best-effort-may-clobber, and the operation says so out loud. Import with
`--require-if-match` — or set `x-revl-require-if-match: true` at the document
root — to refuse the promotion entirely on any endpoint that claims no token.

What none of this closes: idempotence is not reversibility, and no document
proves either. A soft delete, a re-stamped server-assigned id or a dropped audit
history is invisible here, and the generated source marks that residue OPEN on
the operation rather than quietly rounding it off. The real closure is the item
37 verified round-trip, not an annotation.

## 2. Path + method → one service operation

The default is `<method>_<path>`, with template segments spelled `by_<name>`:

| Operation | revl |
|---|---|
| `GET /pets` | `get_pets` |
| `GET /pets/{id}` | `get_pets_by_id` |
| `DELETE /pets/{petId}` | `delete_pets_by_pet_id` |
| `GET /pets/{petId}/toys/{toyId}` | `get_pets_by_pet_id_toys_by_toy_id` |
| `GET /` | `get` |

The rule keeps every segment, so it is **total**: no two `(method, path)`
pairs can produce the same name. Nothing is singularised or elided — a rule
that turns `/pets` into `pet` is a rule that has to know English, and it makes
`GET /pets/{id}` and `GET /pets/mine` fight over one name.

An **`operationId`, when the author gives one, wins** — it is their own name
for the operation, and it reads better (`listPets` → `list_pets` beats
`get_pets`). The specification requires `operationId`s to be unique, but two
of them can still collide once case is normalised (`listPets` and `list_pets`
both become `list_pets`), so the importer checks. **On collision it refuses**,
naming both operations by method and path, and asking for a distinct
`operationId` on one of them. It does not disambiguate by appending a number:
a generated `list_pets_2` is a name nobody can look up in the spec.

One service is generated per document, named from `info.title` (`Pet Store` →
`PetStore`, provision key `pet_store`) or from `--service`. Grouping by `tag`
was considered and rejected: a tag is optional, an operation may carry several,
and neither "the first tag" nor "one service per tag, duplicated" is a mapping
that survives contact with a real spec. One document, one service, one
provider.

## 3. Schemas → revl types

| OpenAPI | revl | note |
|---|---|---|
| `string` | `Str` | |
| `string` with `format: binary`/`byte` | `Bytes` | |
| `integer` | `Int` | **lossy**: `format: int32`/`int64` do not survive; revl has one integer type |
| `number` | `Float` | same for `float`/`double` |
| `boolean` | `Bool` | |
| `array` with `items: T` | `List[T]` | `items` is required — `List[T]` is homogeneous |
| `object` with `properties` | `type R = { … }` | a revl record |
| `object` with only `additionalProperties: T` | `Map[Str, T]` | |
| `enum` of strings | `type E = A \| B \| C` | a payload-free ADT |
| `oneOf` + `$ref` members + `discriminator` | `type U = A(A) \| B(B)` | case names from `discriminator.mapping`, else the schema name |
| `$ref: '#/components/schemas/X'` | `X` | |
| `nullable: true`, or `type: ["T", "null"]` | `Opt[T]` | |
| a property not in `required` | `Opt[T]` | |
| a `2xx` response with no `content` | no return type | `204 No Content` and friends |
| a component schema that is a scalar, list or map | *inlined at its use sites* | see below |

Names cross conventions: schema names become PascalCase (`pet-tag` →
`PetTag`), and properties, parameters and operations become snake_case
(`weightKg` → `weight_kg`, `petId` → `pet_id`). A name that would collide with
a revl keyword gains a trailing underscore (`type` → `type_`, `match` →
`match_`); a schema name that would shadow a revl built-in is suffixed
(`Result` → `ResultTy`). Every rename is reported as a `// note:` in the
generated header — a silent rename is a trap for whoever reads the output.
An enum case that lands on `Ok`, `Err`, `Some` or `None` is *not* renamed (it
is a legal revl case name) but is reported the same way, because it shadows
the built-in constructor inside the generated module.

**Inline schemas get a name from where they appeared.** A request body on
`searchPets` becomes `type SearchPetsBody`, a response becomes
`<Op>Response`, and a nested inline object under `Pet.address` becomes
`type PetAddress`. Two schemas that would land on one revl name are refused
rather than merged.

**Optional and nullable collapse.** revl's `Opt[T]` does not nest, so a
property that is both absent-able and `null`-able is one `Opt[T]`: "absent"
and "null" are the same value on this side of the boundary. The header says so
whenever it happens, because the round trip back out is where that matters.

**Recursion needs no special case.** `Pet.companion: Pet` and
`Node.children: List[Node]` are both fine — a revl record field may name the
record it belongs to. This was on the list of things to refuse if it could not
be expressed; it can be.

### Why scalar component schemas are inlined rather than declared

`"Sku": {"type": "string"}` does **not** become `type Sku = Str`. In revl,
`type X = Y` declares a single-case *variant* named `Y` — an ADT, not an alias
(docs/syntax-2.0.md §2; revl has no alias form). Emitting it would compile and
mean something entirely different. The importer therefore resolves such
schemas at their use sites, and records what it did:

```
// note: `#/components/schemas/Sku` is `Str` — inlined at its use sites
// (revl has no type alias: `type X = Y` would declare a variant)
```

This is the same decision, for the same reason, that `revl import wit` makes
about WIT's `type x = string`.

## 4. Parameters, bodies and responses

- **`in: path`** parameters come first, in the order the path template uses
  them, so the signature reads like the URL. A template variable that is not
  declared, or a path parameter that is not in the template, is refused.
- **`in: query`** parameters follow, `Opt[T]` unless `required: true`.
- Path-item-level `parameters` are merged into every operation under that
  path.
- The **request body** is the last parameter, named `body` (`request_body` if
  something already claimed `body`), `Opt[T]` unless `required: true`.
- The **response** is the lowest 2xx status. A document declaring several 2xx
  payloads gets a note saying which one was used — revl operations return one
  type. No 2xx at all is a refusal: `default`-only says nothing about what
  success looks like.
- Only JSON payloads are typed: `application/json`, `application/json;…`, and
  `*+json`. Anything else is refused by media type.

## 5. What it refuses, and why

The rule is: **refuse rather than emit something wrong.** Each refusal names
the construct, its JSON pointer, a best-effort source line, and the way
forward. A JSON pointer rather than only a line, because `json.loads` does not
keep line numbers and a pointer is the precise location in a structured
document; the line is recovered from the raw text as a convenience and is
never trusted for more.

```console
$ revl import openapi tests/fixtures/openapi/inheritance.json
error: tests/fixtures/openapi/inheritance.json:31: unsupported OpenAPI
construct: `allOf` at #/components/schemas/Item/allOf
  flatten the members into one schema with all their properties, or `$ref` the
  base schema as a single property; merging them here would have to guess what
  a conflicting property means
```

| Refused | Why | What to do instead |
|---|---|---|
| `allOf` | merging is where generators quietly go wrong: two members can disagree about a property's type or its requiredness, and there is no correct answer to pick | flatten the members into one schema, or `$ref` the base as a single property |
| `anyOf` | it admits *several* members at once, which is not a sum type and has no revl spelling | if exactly one was meant, write `oneOf` with a `discriminator` |
| `oneOf` without a `discriminator`, or with non-`$ref` members | a revl ADT case is chosen by *name*; an untagged union has no case names, and an inline member has nothing to name it after | add `discriminator: {propertyName: …}`; lift inline members into `components/schemas` |
| `not` | revl types are structural, with no negation | name the shapes you accept |
| a free-form `object` (no `properties`) | a revl record has fixed, typed fields; there is no dynamic value type to fall back on | list the `properties`, or give `additionalProperties` a schema so it becomes `Map[Str, T]` |
| `properties` **and** open `additionalProperties` | a revl record holds exactly its declared fields and cannot carry the extras | `additionalProperties: false`, or drop `properties` |
| a schema with no `type` (`{}`) | an unconstrained schema has nothing to become | give it a `type`, or model the payload as `Str` and parse it in the host body |
| a non-string `enum` | an ADT case is a name, and `2` is not one | drop the `enum` to keep the scalar, or use string values |
| `type: ["string", "integer"]` | revl values have one type | `["T", "null"]` is understood as `Opt[T]`; anything wider needs a discriminated `oneOf` |
| `array` with no `items` | `List[T]` is homogeneous and needs its `T` | add `items` |
| a `$ref` outside `#/components/schemas/` (including `$ref` path items, parameters, request bodies and responses) | this importer reads exactly one document, like its siblings | inline the target, or bundle first (`redocly bundle`, `swagger-cli bundle`) |
| `in: header` / `in: cookie` parameters | a header is transport, not an operation argument, and dropping it silently would change what the operation means | set it inside the generated `extern`'s host body — that is what the host block is for — then delete the parameter |
| a non-JSON request body or response | this importer types JSON payloads | represent the payload as `application/json`, or drop it and handle the encoding in the host body |
| an operation with no 2xx response | there is no success payload to type | declare the concrete success code |
| two operations, or two schemas, that generate one revl name | a service's methods, and a module's types, share one namespace | give one a distinct `operationId`, or rename the schema |
| an OpenAPI 2.0 (Swagger) document | 2.0 spells bodies, responses and schemas differently | convert first (`swagger2openapi`) |

Refusing `allOf` is the one that will bite most often — it is the standard
inheritance idiom, and plenty of real specs lead with it. That is the honest
outcome for now: a correct `allOf` merge needs a conflict policy this importer
has no basis to invent, and the failure mode of guessing (a field silently
typed from the wrong member) is exactly the kind of quiet wrongness the rest of
this document is arguing against. Flattening the schema by hand takes a
minute and leaves the result readable.

## 6. `--backend`, and the missing one

The generated `extern` bodies are **stubs** — the typed boundary is generated,
the HTTP call is not — and `--backend` chooses which tier they are tagged for.
The URL, headers, auth, query-string encoding and status handling all belong
inside them.

`ts` (the default), `py` and `rust` are offered. There is deliberately **no
`wasm`**: an HTTP client has no meaning on the cordis-wasm tier, which is
i32-only today (`backends/wasm/emit.py`), and offering the flag would generate
a plausible file that could never lower. `revl import wit` defaults to `wasm`
for the opposite reason — that is where a WIT world lives.

## 7. JSON, and what happens to YAML

The JSON path is the standard library's `json`, hand-wired; there is **no new
dependency**, which is the whole project's standing rule.

YAML is *delegated, never approximated*. If PyYAML happens to be importable it
is used; otherwise the refusal carries the one-line conversion:

```
error: spec.yaml:0: this document is not JSON, and no YAML parser is available
  revl has no dependencies, and this importer will not guess at YAML rather
  than parse it. Convert the spec once — python -c "import sys,yaml,json;
  json.dump(yaml.safe_load(open(sys.argv[1])), sys.stdout)" spec.yaml >
  spec.json — or install PyYAML, which this importer will use if it is
  importable
```

A hand-rolled YAML subset would parse the common case and then mis-read an
anchor, a folded scalar or a flow collection *silently*, producing revl that
compiles and describes the wrong API. That is the single failure mode this
family exists to prevent, so it is not worth the convenience.

## 9. The family, closed

With `openapi` landed, roadmap §4 is complete: `revl mcp import`,
`revl import wit`, `revl import openapi`. All three take the same shape — a
`service` plus `extern`s plus a provider component — and the same trust
direction, with the evidence available to each getting steadily better:

| Importer | Evidence about reversibility | Default |
|---|---|---|
| `revl mcp import` | `readOnlyHint: true`, a purpose-built assertion by the server author | `emission` |
| `revl import wit` | none whatsoever | `emission`, weakened only out of band |
| `revl import openapi` | the HTTP method, normative under RFC 9110 §9.2.1 | `emission`, weakened by a safe verb |

The pattern worth keeping from all three: an importer may weaken a
classification only on an explicit, positive claim, and it must write down
whose claim it was.
