## The embeddable compiler: revl as a safety kernel (post-v3.0 arc)

These build on two settled results. First, the self-hosted compiler is a
PURE-FUNCTION pipeline (`selfhost/compile.rvl`: `admit(source) -> verdict`,
`compile_to(source, tier) -> output`, no cordis dependency), already compiled
and run natively on py + rust (items 283/284 profiled its rust runtime). Second,
per-tool-call witnessed effects + session commit + six-tier crash recovery
shipped (243/244/245/322). Together they turn revl from "a language with a CLI"
into an admission gate you EMBED in any host runtime. The remaining lever the arc
depends on is the self-host coverage frontier: the function/type surface is
byte-exact today, the component/method-body surface is the `revl`-column `lim`
frontier in docs/conformance.md.

332. **Embeddable-gate API + packaging (the foundation of this arc).** Emit
     `selfhost/` as a real consumable library per tier: first a Rust crate and a
     Python package (npm / wasm-component later), exposing a STABLE
     `admit(source) -> verdict` / `compile_to(source, tier) -> output` surface so
     a host program imports the revl admission gate as a native function - no
     subprocess, no cordis dependency, because the compiler is pure `fn`s. Design
     the API boundary (error/verdict shape, versioning) once, tier-agnostic.
     Exit test: a standalone Rust binary depending ONLY on the published crate
     calls `admit` on a component and returns the same verdict as `revl compile`,
     and `compile_to` is byte-identical to the reference on the covered corpus.
     Blocks 333-338. `selfhost/` + a new crate/package build. Depends on the
     self-host coverage frontier above.

333. **In-process admission gate for agent frameworks (rust/py).** With 332, an
     agent tool-generation loop calls the gate INLINE at ~0.165 ms/candidate: no
     `revl mcp serve` process, no IPC. The agent's own process holds the compiler;
     every proposed tool is admitted before it can run. Exit test: an example
     Rust/py agent harness embeds the gate, admits/rejects a batch of proposed
     components in-process matching the CLI verdicts, round-trip cost measured.
     Relates to docs/mcp-bridge.md + item 50 (the token economy). Needs 332.

     revert agent components live (THE headline of this arc).** A running host
     (rust/py) that embeds BOTH the admission gate (332) and the witnessed-effect
     runtime can compile + admit + hot-swap an agent-generated component AT
     RUNTIME, run it under revertible effects, and roll back residue-free on abort
     (the 243/245/322 machinery). The "self-mutating" banner claim made real: a
     component proposes a component, the embedded compiler decides, the runtime
     reverts on rejection - all in one process, with compile-time guarantees.
     Exit test: a live composition accepts an agent-proposed component, runs a
     tool call under witnessed effects, and on an injected fault reverts
     residue-free without leaving the process. Builds on 243/244/245/322 + 332.

335. **Edge / browser / serverless admission (the wasm gate).** Compile the
     admission gate to wasm so it runs client-side: a web playground / IDE that
     type-checks + admits revl with no server round-trip, and an edge-worker gate
     that admits agent code sub-millisecond with no cold-start Python. Exit test:
     the wasm-compiled `admit` runs in a browser / wasmtime host and returns the
