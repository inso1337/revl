# revl 2.0 — implementation roadmap

**Branch:** `v2.0` · **Design:** docs/syntax-2.0.md · **Why:** docs/vision.md ·
**Status:** core complete; hardening & exit-criterion items below

`v2.0` = realms/interception (`ir_version: 2`) **plus** the full-language
proposal in syntax-2.0.md (`ir_version: 3`) — the pure-expression stratum
grown into a self-hosting-capable language without weakening G1–G8.

## IR versioning (the contract)

| ir_version | carries | backends |
|---|---|---|
| 1 | v1 documents | all — frozen, byte-identical |
| 2 | realms/interception (`isolate`/`intercept`) | cordis-py, cordis (TS), cordis-rs, cordis4j, wasm (realm namespaces) |
| 3 | full-language (`fn`, `type`, `match`, `extern`, `test`) | cordis-py, cordis (TS), cordis-rs, cordis4j, wasm (typed core tier) |

A document's `ir_version` is the *maximum* feature tier it uses. v1 sources
must keep emitting `ir_version: 1` byte-identically (the frozen-reference
invariant) and their goldens must never regenerate.

## Agent, interop & test surface (ranked)

Five capability questions, answered against the code as it stands. Ordered by
value, not by size. Each names what exists, what is genuinely missing, and the
recommendation.

### 1. ✅ `revl_swap` and in-memory compilation — done

Both gaps closed. `compile_source` now carries the ambient manifest and
`modules` (in-memory sources for `use`), so inline source is compiled without
touching the disk — the temp-file shim is gone, and a virtual source stands in
for the file it names in both root loading and `use` resolution. The server
holds a live composition (`mcp/session.py`, a trace-capturing subclass of
`run._Driver`, so the lifecycle is the same code `revl run` uses and stdout
stays clean for JSON-RPC) and exposes `revl_load`, `revl_call`, `revl_swap`,
`revl_rollback`, `revl_unload`, `revl_state`.

The whole point in one line: **an agent iterates on a component that has no
file, tests it by calling it, and proves it leaves no residue before anything
is written out** — and a rejected candidate cannot deploy, because the compile
runs before the transition, so the running composition keeps serving.

Covered by `tests/test_mcp_session.py` (skips where cordis-py is absent).

### 1b. Self-evolution — done, and what building it exposed

`demo/self_evolve.py` (+ `tests/test_self_evolution.py`) is a composition
that rewrites one of its own components: `Evolver` requires an `Assistant`
(the model, an ordinary coeffect) and a `Runtime` (the compiler, another
ordinary coeffect), asks for a new component, and the runtime admits or
refuses it against what is currently loaded. An admitted candidate becomes
the next generation; a refused one never reaches the queue and the
composition keeps serving. Nothing touches the filesystem.

Two design points that make it safe rather than merely clever: `propose`
**queues** rather than swapping synchronously (a component asking to replace
the composition it belongs to would be asking to be disposed inside its own
method), and the assistant is a **swappable provider** — the stub is
deterministic for CI, and pointing it at a real model is a provider swap,
not a code change.

Building it surfaced three language gaps. Two are fixed:

- ✅ **An emission's return value was unusable.** `emit` was a statement that
  discarded its value — fatal for the canonical emission that *returns* data
  (an LLM completion, an HTTP GET). `emit` is now also an expression prefix,
  so `return emit assistant.complete(p)` and nested forms work while the
  marker stays at the call site (G4's actual point). The G4 upper-bound walk
  was extended to see emissions in value position.
- ✅ **`emit` was rejected on an `emission` extern**, though a service
  emission required it — an asymmetry with no justification. `emit` now
  accepts either.

Both are now fixed too:

- ✅ **A provision key colliding with a host context member** used to compile
  and then die at activation (`provides runtime: …` → `property "runtime" is
  already declared as accessor`). The reserved set is host-specific, so the
  rejection lives in the emitters that know their own surface: the cordis-py
  and cordis (TS) backends reject such a key with the name and the reason.
  The rust/java/wasm tiers do not expose a context object this way.
- ✅ **Provide-method bodies now admit plain bindings.** `let x = <expr>`
  names an intermediate value (`let x = effect … undo …` still means the
  acquisition — the parser branches on the `effect` keyword), `var` plus
  assignment is available where a method needs to accumulate, A3 renaming
  applies, and an activation body still refuses a plain binding with a
  diagnostic pointing at the effect form (G6). Lowered as `let`/`assign`
  steps and implemented across **all five** emitters — python, TypeScript
  and java as native locals, wasm as declared `(local $x i32)` slots, rust as
  `let`/`let mut` in all three of its method paths (its pure path now emits a
  statement sequence instead of requiring a single return).

### 1c. ✅ Cross-tier portability, and the divergences it found

`tests/test_cross_tier.py` runs one source through **all five** emitters and
asserts they agree. It needs no toolchain (every emitter is pure Python), so
the floor is cheap to hold, and a tier that genuinely cannot express
something is listed in `EXPECTED_LIMITS` with its reason — which keeps a
deliberate restriction distinct from an oversight.

Writing it immediately paid for itself. Method bindings had shipped to four
tiers, and closing the rust gap surfaced two more divergences of the same
shape — a construct accepted by some emitters and unknown to others:

- **TypeScript could not render pure 2.0 expressions inside component or
  method bodies.** It carries two expression renderers (one for component
  bodies, one for `fn` bodies) with disjoint kind sets, so `let msg = prefix
  + name` — a pure `bin` beside a `req` call — hit `unknown expression kind
  'bin'`. They now fall back to each other, with the document's v3 context
  published for the duration of `emit`.
- **wasm had the same split**, so i32 arithmetic in a method body was
  refused although it is precisely this tier's native shape. Its component
  renderer now lowers `bin`/`un` to i32 instructions directly.

The lesson worth keeping: every one of these was a *renderer* divergence
rather than a semantic one, invisible to any single-tier test, and each was
found within minutes of running one source through all five.

### 1d. Conformance matrix — the gap list (docs/conformance.md)

`tools/conformance.py` runs 48 constructs through all five emitters and
reports what each tier does. python is the reference: **0 gaps**. The rest,
worst first, deliberate tier limits excluded:

1. **`??` is unimplemented on rust, java and wasm** — a documented 2.0
   operator that is python-only today (TypeScript has it in `fn` bodies but
   not component bodies). The lowering is well-formed; three operator cases
   are simply missing.
2. **Calling a pure `fn` from a component body fails on TypeScript and
   wasm** — the `fn` call node is in neither renderer's kind set. This one
   cause is 9 of TypeScript's 12 refusals.
3. **`match` is not usable in a component or method body** — frontend-level,
   so every tier is equally affected; ADT-consuming components must call out
   to a `fn`.
4. **A bare `return` does not parse**, though the IR and two emitters already
   model it — the natural body for a void service operation.
5. Tier-local: TypeScript has no `if` step in component bodies (so `fail`
   guards do not lower) and misreads `??` there; java *rejects* a `fn` whose
   name collides with a Java keyword instead of renaming it (A3 already
   solves this for bindings); rust cannot read `config` inside a guard
   expression; wasm's component renderer lacks `if`/`list`/`record`/`fn`.

Every one is a **renderer** divergence — a well-formed node with no case in
some backend — never a semantic one, and all are invisible to single-tier
testing. The structural fix after the immediate gaps: one expression
renderer per backend covering every IR kind, with tier limits as explicit
refusals rather than missing cases. python, the only tier with a single
renderer, is the only tier with no gaps.

### 1e. ✅ Conformance sweep — all real gaps closed

Three agents in parallel (one per backend directory) plus a frontend batch
took the matrix from 12/5/5/32 real gaps to **zero**: python 0, typescript 0,
rust 3, java 3, wasm 19 — and every remaining refusal is a deliberate tier
limit with a one-line justification (docs/conformance.md).

Follow-ups this surfaced, none blocking:

- ✅ **The matrix's blind spot is closed.** It used to check only that an
  emitter did not raise. `tools/validate.py` now *compiles* emitted output per
  tier (`cargo check`, `javac` against the cordis4j stubs, `wasmtime` module
  validation), and a dedicated `conformance` CI job installs node, cargo,
  JDK 21 and a pinned wasmtime so all five tiers are validated on every push —
  previously four of them skipped in CI. `--check-toolchains` fails rather
  than reporting a silently unvalidated tier. The 16 real emitter bugs this
  exposed (3 rust, 13 java, incl. the `requires`-capture bug named here) are
  fixed, not baselined: `KNOWN_FAILURES` is empty. Two of them failed on
  *both* tiers from one upstream cause — host builtins had no declared
  signatures, so each backend carried a private copy and four tiers disagreed
  about a contract nobody enforced; `_HOST_ARG_SIG`/`host_check` now type
  them in the frontend.
- **The component IR dialect is not uniform** — `Some(x)`/`None` arrive in
  v3 spelling inside component bodies while their neighbours use component
  spelling, so every backend normalizes it privately. The frontend should
  emit one dialect per position.
- **`call` is ambiguous by kind across dialects** (component `target`/
  `method` vs 2.0 `callee`/`args`), the one node where the two-renderer
  split fails *silently*. A constraint on the single-renderer refactor.
- ✅ **Doc examples are compiled, and the collection floor is guarded.** Every
  fenced ```revl block in README + docs is now checked, under a four-way fence
  convention — `program` (must compile), `fragment` (syntax-checked inside
  scaffolds), `sketch` (must *not* compile, so it fails when the feature lands
  and tells the author to promote it), `reject` (with an optional diagnostic
  code that must match). It was written because all three flagship `UserCache`
  examples had silently stopped compiling when G4 gained its upper-bound
  direction — one of them contradicting a rule stated 70 lines below it. In the
  same pass `tests/test_mcp_session.py` went from collecting **zero** items (a
  module-scope `importorskip` aborted the whole file, taking three runtime-free
  tests with it) to 5 passing, with `tests/test_collection_guards.py` pinning
  that class of bug shut.
- ✅ **The interop seam checks the method, not just the key.** The py and TS
  stubs dispatched any method name off the wire while validating only the
  service key — the allowlist already existed on the proxy side and in the
  placement spec, and simply was not given to the stub. Probes in a placement
  file are now parsed (`ast.parse` + `literal_eval`) instead of `eval`'d with
  full builtins, `--placement` preflights like plain `revl run`, and
  docs/interop-bridge.md states the trust model it had never stated: same-user
  sockets in a 0700 dir, no authN/authZ, values by copy, and what it is *not*
  — not a sandbox, not a multi-tenant boundary.
- **Test-hygiene hazards** (closed, see "Open" item 7): three claims with no
  gate behind them — a cold TypeScript checkout collecting two fewer tests
  than a warm one, the wasm tier's 25 runtime tests skipping whenever
  wasmtime was absent, and the rust cargo gates verifying nothing on a
  machine with no route to crates.io. All three read green while checking
  less, which is the failure mode this section keeps rediscovering: the
  hazard is never a red test, it is a test that was never collected.

### 2. ✅ Lifecycle tests — the paradigm's own guarantee, asserted in-language

**Landed** (syntax-2.0 §7.1, `tests/test_lifecycle*.py`). `lifecycle` is a
**modifier, not a new top-level form** — the precedent is `verified fn`, an
adjective that changes what a body may contain without changing what the
declaration *is*. The grammar delta is one token in one position, which is
what §8's prompt-size requirement demands. A body is a script over a live
composition: `load C with { … }`, `call key.op(…)`, `let x = call …`,
`unload C`, `assert no_residue`.

The assertions bite, which is the whole point: a leaky `undo` is caught via
R1 (`open() with no close()`) and a forgotten `unload` via R4's introspection
delta — both proven by tests that *expect failure*, on the cordis-py
reference tier. The other four tiers refuse a lifecycle test with a named
`EmitError` rather than half-implementing it.

**Was:** `test "name" { assert … }` lowered through the *pure-statement* path
(`_lower_tests` → `_lower_pure_stmt`), so a test could only exercise `fn`s —
teardown correctness, the thing most worth testing in a language about
revertible composition, was expressible only in each backend's own Python/TS
suite. The shipped form:

```revl
lifecycle test "cache reverts cleanly" {
  load UserCache with { }
  call cache.put("k", "v")
  unload UserCache
  assert no_residue          // R4, asserted from inside the language
}
```

Natural companion to `verified`; the backends already implemented every
primitive it needed (R1–R5 suites). Examples: `examples/lifecycle_cache.rvl`,
`examples/lifecycle_leak.rvl`, and seven rejection fixtures under
`examples/rejections/lifecycle_*.rvl`.

### 3. ✅ Cross-tier test execution — `test` is a conformance harness

**Landed:** `revl test <files> [--backend py|ts|rust|java|wasm|all]` reuses
each backend's existing runner — py executes `REVL_TESTS` in-process, ts runs
the emitted vitest blocks, rust runs `cargo test` over a throwaway crate,
java compiles against the cordis4j stubs (or the real classes on
`REVL_CORDIS4J_CLASSES`) and runs `REVL_TESTS` on a JVM, and wasm is refused
(test blocks do not lower to the substrate; the runner is host-side). A tier
whose toolchain is absent is *skipped with a reason* (vitest missing, no
working JDK, crates.io unreachable) — never reported as passing. `--all`
runs every tier that is present and fails the run if any available tier
fails: every `test` block is now a portability assertion, gated only by the
toolchains in front of you. The cheapest high-value change on this list is
done.

### 4. Import codegen family — wrap what already exists

**Today:** libraries and modules wrap cleanly via `extern` + host blocks, with
multi-backend bodies (`= @ts {} = @py {}`) keeping the component portable.
Binaries wrap by hand in the idiomatic shape — `extern acquire fn spawn(...)
undo kill(...)` plus `emission` for writes — and the subprocess shows up on the
G8 audit. `revl mcp import` is the only *automated* importer.

**Gap:** every other existing interface (OpenAPI service, WIT world, C header)
is hand-transcribed. Note the standing cost, which is by design: an extern is
per-backend and *trusted* — revl types the boundary, never the inside.

**Do:** grow the family — `revl import openapi|wit|mcp`. WIT first: the wasm
tier's types line up one-to-one with WIT worlds (docs/interop-bridge.md), so
it is codegen rather than design.

- ✅ **`revl import wit` landed** (`src/revl/import_wit.py`, docs/import-wit.md,
  39 tests). Hand-written WIT parser, no new dependency. A WIT interface becomes
  a `service` + `extern`s + provider component; records/variants/enums map
  one-to-one, aliases are *inlined* (revl's `type X = Y` declares a variant, not
  an alias), and resources/handles/`stream`/`future`/`flags`/`tuple` are refused
  by name, line and remedy rather than approximated. The emission question is
  settled the way `revl mcp import` settles it: WIT asserts nothing about
  reversibility, so **every operation is `emission` unless a recorded human
  claim says otherwise** (`/// @revl:pure` in the WIT, or `--pure` at import
  time) — and G4 keeps the weakened form honest, since the compiler rejects a
  plain operation whose provider reaches an emission. The types line up as
  predicted; what did *not* is the tier — cordis-wasm is still i32-only, so a
  string/record-carrying world imports to valid revl that only the hosted tiers
  (`--backend py|ts|rust`) can lower today.
- ✅ **`revl import openapi` landed** (`src/revl/import_openapi.py`,
  docs/import-openapi.md, 85 tests) — §4 is now complete. An OpenAPI 3.x document
  becomes a `service` + `extern`s + provider; schemas map to records, enums to
  ADTs, discriminated `oneOf` to a variant, `additionalProperties` to `Map`,
  optional/`nullable` to `Opt`, and recursive `$ref`s need no special case.
  `allOf`/`anyOf`/`not`, untagged `oneOf`, free-form objects, header/cookie
  parameters and non-JSON payloads are refused by name, JSON pointer and remedy.
  This is the first importer where the *document* carries reversibility
  evidence: RFC 9110 §9.2.1 makes `GET`/`HEAD`/`OPTIONS`/`TRACE` safe, so a safe
  verb is the explicit in-band claim that weakens the family's `emission`
  default — while `PUT`/`DELETE` stay `emission` (idempotent is not reversible),
  the generated header records that safe-by-spec is the API author's claim and
  not a checked property, and `--pure`/`--emission`/`x-revl-emission` override in
  both directions with an explicit emission claim always winning. No new
  dependency: stdlib `json`, and YAML delegated to PyYAML if importable rather
  than approximated by a subset parser.

### 5. Service versioning, then (maybe) a component repository

**Today:** `--placement` composes **py ↔ node ↔ rust ↔ java** in one lifecycle,
symmetrically (every tier can both consume and provide across a seam) and
reactively (every tier turns provider death into withdrawal), with all four
verified end to end via `revl run --placement … --once`.
`distributability` is a *checked* verdict — an address-space-bound service is
refused at the seam rather than silently marshalled.

**Symmetry: reached** (`e349487`). Rust both consumes *and* serves across a
seam — `backends/rust/emit.py` generates the proxy/stub/dispatcher per
composition, the placement runner is generic (no composition-specific code),
`placement.py` regenerates `components.rs` from the running IR before
`cargo build`, and the no-serve guard is gone. Java gained a *reactive*
runtime on real cordis4j (JDK 21): a monitor connection turns provider death
into withdrawal, so a consumer unloads reactively (R2/R3) instead of seeing an
exception; `placement.py` auto-selects it when JDK 21 + cordis4j classes are
present and says so in the placement summary, falling back to the stub
otherwise.

Both narrower limits closed in turn (`cab678e`), making **rust a full
reactive participant** alongside py/node/java:

- **Full type marshalling** — the generated proxy/stub marshal any
  non-opaque type through serde (records, ADT enums, `Map`, `Result`, and
  their `List`/`Opt` nestings), not just scalars. Emitted records/enums carry
  serde derives, and the IR `types` dict is threaded through service-trait and
  bridge emission so a record in a signature emits as its concrete struct
  rather than an opaque `Value`. Scalar branches are byte-identical, so the
  golden holds. Fixture: `examples/rec.rvl`.
- **Peer-death monitor** — one monitor thread per proxy holds a connection to
  the provider socket; on EOF it disposes the proxy, so the cordis-rs consumer
  deactivates reactively (Active → Pending, no panic). The hold now
  distinguishes graceful stdin-close from peer death.

**What remains open at the seam:**

- ✅ **ADT/`Result` wire encoding is now cross-language** (`70d0ba6`): the
  tiers agree on one canonical encoding rather than rust's serde-tagged
  form, so an ADT seam is no longer rust↔rust only. This was the "settle it
  once" call flagged here — it was settled.
- **The opaque host `Value` stays unmarshalled**, by design — it is the
  untyped escape hatch, and marshalling it would mean inventing a type for
  something the language deliberately has none for.
- Not every service may cross, by design (async contract + value types) —
  `distributability` refuses the rest at the seam rather than marshalling it
  silently.

**On a repository:** not yet. The admission gate already answers the question
cargo cannot — not "does this version resolve?" but "does this fit *this
running system*?" — and the manifest is already a publishable JSON artifact
carrying load order, coeffects and the G8 boundary. But publishing would force
an unsolved problem prematurely: revl links by **key identity** (`db:
Database`) with no versioning or structural compatibility (paper §6.6). Two
independent authors both providing `db` collide, and a provider that reshapes
`Database` breaks consumers with no semver to catch it.

**Do:** key namespacing + an interface-compatibility check (the admission
gate's drift detection is the seed) **before** any registry. A registry when
there is a second author, not before.

## Toward early production

The items above complete and harden the *language*. These turn it into
something a second team can build on and operate. Multi-runtime stays (see IR
versioning and the Cordis backends); nothing here blesses a single tier.

### 1. Soundness: close or fence every gap, prove each with a rejection test

The one promise revl sells is that the checker is the admission gate: a
component that would corrupt a running system cannot compile. That promise is
only as strong as its weakest silent gap, so the soundness surface has to be
complete and self-proving.

- ✅ **Enumerate the contract.** Every guarantee G1-G8 and lifecycle rule
  A1-A8 is now accounted for in the executable spec. Ten (G1-G4, G6, G8, A1,
  A2, A6, A8) have a rejection fixture in `examples/rejections/` that the
  checker must refuse with the guarantee-naming diagnostic. The other six are
  **not independently checker-rejectable** — G5 and A5 are prevented by the
  grammar (an `effect` in an `undo`/teardown position is a parse error, and
  `compensate` is an optional slot with no "required-but-missing" program),
  G7 is derived-by-lowering (Thm. 16, not a compile check), and A3/A4/A7 are
  lowering transforms (identifiers renamed, `$$` escaped, flags advisory) —
  each documented, with where it is actually enforced, in a block after the
  `REJECTIONS` table. The one plausible hole checked (an emission reached from
  a teardown body) is sound: it stays on the G8 audit surface. So the suite
  *plus that block* is the definition of sound, not a sample.
- **Close the known holes** (today: "sound where declared, silent where
  unknown", item 12):
  - ✅ stdlib method return types are now typed on known receivers, so
    `charAt`/`charCodeAt` misuse is a compile error (`s.charAt(0) + 1` where
    an `Int` is expected is rejected). Host-*provenance* objects (an extern's
    return) still infer to unknown and stay silent — fenced in
    docs/contract-errata.md, on the G8 audit surface.
  - the "Typing follow-ups" under Next (generics instantiation, match-arm
    check-position, component-setup op sweep) are soundness work, not
    ergonomics; treat them as blockers here.
  - nullary user-ADT constructors as values inside `test`-block expression
    scope — closed: a `test` body is the same expression scope a `fn` body
    is, so a bare `FirstTime` resolves as a value
    (`test_nullary_ctor_resolves_in_test_block` pins it).
- **Fence what stays open.** Anything not closed for a release gets a named
  entry in `docs/contract-errata.md` as a *known* unsoundness, with its trigger
  and blast radius, the way the cordis-rs A1 divergence already is. "Silent
  where unknown" is acceptable only when it is loud in the errata.

Exit test: no reachable program can violate a guarantee without either a
compile error or a documented errata entry.

### 2. `revl run`: one command, on a released runtime, any tier

Today the loop stops at IR (`compile` / `audit` / `test` / `fmt`), then a
hand-written Python driver (`backends/python/demo.py`) drives a runtime that
lives on a feature branch (`cordis-py@harden-fiber-lifecycle`). Close the loop
without giving up multi-runtime.

- `revl run <manifest> [--backend py|ts|rust|java]` boots a composition on the
  chosen Cordis runtime and streams the lifecycle/host trace, with no
  host-language driver. Backend-selectable by design; py is the default
  runnable tier.
- Pin each backend to a *released* runtime with a documented R1-R5 contract:
  cordis-rs already targets 0.3.0 and cordis4j a source tag; give cordis-py a
  tagged release cut from `harden-fiber-lifecycle` so nobody builds against a
  branch.
- Promote `demo/live.py` to `revl run --watch`: the file-watching hot-swap loop
  as a first-class command, not an example script.

Exit test: `git clone && revl run examples/...` prints a running composition on
every supported tier with no host-code edits.

### 3. Lighthouse workload: glitch agents (the self-deploying harness, DESIGN §1)

DESIGN §1's second motivation is a self-evolving agent harness: agents author
components, and revl is "the language such a harness could require its own
components to pass" before they self-deploy. **glitch agents** are the candidate
dogfood for exactly that. Running one real workload on revl is what turns
"research language" into "the language we run X on", and it will order the work
in 1 and 2 faster than any roadmap guess.

Shape to validate:
- agents emit `.rvl` components; `revl compile`/`audit` is the pre-deploy
  admission gate (reject means do not deploy, with the guarantee-naming
  diagnostic fed back to the generating agent);
- accepted components hot-swap into the running agent system via
  `revl run --watch`, with derived LIFO teardown on rollback so a bad
  generation reverts to no residue;
- the G8 boundary surface (externs, emissions) is the review surface for
  anything a generated component reaches outside its declared capabilities.

Open questions (need input to sharpen this entry):
- what glitch agents run on today (runtime and language), and where revl
  components would slot in;
- which backend tier they target first (py?);
- whether agents author whole components or fragments, which sets how much of
  `revl run --watch` is needed first.
