# revl 2.0 — implementation roadmap

**Branch:** `v2.0` · **Design:** docs/syntax-2.0.md · **Status:** core complete;
hardening & exit-criterion items below

`v2.0` = realms/interception (`ir_version: 2`) **plus** the full-language
proposal in syntax-2.0.md (`ir_version: 3`) — the pure-expression stratum
grown into a self-hosting-capable language without weakening G1–G8.

## IR versioning (the contract)

| ir_version | carries | backends |
|---|---|---|
| 1 | v1 documents | all — frozen, byte-identical |
| 2 | realms/interception (`isolate`/`intercept`) | cordis-py; TS/wasm reject by version |
| 3 | full-language (`fn`, `type`, `match`, `extern`, `test`) | cordis-py + TS; wasm rejects by version |

A document's `ir_version` is the *maximum* feature tier it uses. v1 sources
must keep emitting `ir_version: 1` byte-identically (the frozen-reference
invariant) and their goldens must never regenerate.

## Done (dependency order as built)

1. ✅ **Lexer** — multi-char operators, 2.0 keywords, template literals.
2. ✅ **Types & data (§2)** — records, generics `[]`, enums, ADTs, built-ins,
   `T?` sugar.
3. ✅ **Functions & expressions (§3.1–§3.5)** — `fn`/`pub fn`, TS-subset
   expression layer, local mutation (`var`/`while`/`for-of`, non-escaping),
   `==`/`===` equivalence, §3.3 exclusion diagnostics.
4. ✅ **`match` (§3.3)** — exhaustiveness-checked ADT eliminator.
5. ✅ **Modules (§1)** — `use`/`pub`, module-private default, import-cycle check.
6. ✅ **Services 2.0 (§5)** — `async fn`, `commutative`.
7. ✅ **Components 2.0 (§4)** — block-effect form, `fail` (L-Raise).
8. ✅ **Host blocks (§6)** — classified `extern … = @ts {} = @py {}`, G8 audit
   surfaces externs/host code transitively.
9. ✅ **`verified` & `test` (§7)** — `revl test` runner, totality tier.
10. ✅ **Migration (§9)** — template literals; legacy `$` forms rejected with a
    `revl fmt --migrate` hint.
11. ✅ **Stdlib surface** — docs/stdlib-2.0.md (`length`/`push`/`slice`/
    `charAt`/`charCodeAt`/`indexOf`/`concat`; persistent semantics; unknown
    method = compile error). Turing-completeness demonstrated by execution.
12. ✅ **Sound typing & null safety** (`542bbad`) — bidirectional checking in
    `src/revl/typecheck.py`: sound where declared, silent where unknown.
    Service/fn call arguments and returns, provide-method signatures from the
    service (A6), `var` type stability, `Bool` conditions, record fields, ADT
    payloads. `null` evicted from expressions — absence is `Opt[T]`
    (`T → Opt[T]` injection allowed; `Opt[T] ↛ T` with an unwrap hint).
    Documented gradual frontier: host-valued objects, single-letter type
    params, the trusted extern boundary (G8).

## In progress

- **syntax-2.0 acceptance benchmark** (§10 of the proposal) — running now on
  a separate agent: 30 specs × syntax variants × models, first-pass compile
  rate + iterations-to-green. Post-hoc for stratum 1 (the gate was skipped);
  its findings feed syntax revisions before merge.

## Next

- **Typing follow-ups** (frontier shrinkage, in priority order):
  - **generics instantiation** — unify `[T]` parameters at call sites instead
    of treating single-letter type names as wildcards;
  - **match-arm checking against the expected type** — arms individually
    checked in check-position (today only the joined arm type is compared);
  - **op sweep inside component setup blocks** — run the checking inferencer
    over block-effect setup statements as the pure-fn paths already do.
- **Self-hosted lexer** — the 2.0 exit criterion (syntax-2.0 §11): the lexer
  as a revl component providing a `tokens` service. Blocked on stdlib
  'Planned' items (Map value type, `Str.split`/`join`) — spec those first in
  docs/stdlib-2.0.md.
- **Merge `v2.0` → `main` and push** (after the benchmark lands); prune the
  `~/Projects/revl-v2` worktree — its `v2/realms` branch is contained in v2.0.
- **wasm tier**: realm namespaces; ir_version 3 support (fn/match lowering to
  WAT) after TS/py parity settles.
- **Dynamic realms** — need instance-parametric components (design work;
  see docs/design-v2-realms.md limitations).
- Minor demo frictions: parameterize runtime import, trace resolved config,
  multi-observer `set_trace`.

## Invariants (checked every step)

- v1 goldens byte-identical; frontend/backend-py/backend-ts suites green
  (currently 164 / 21 / 24).
- Every new rejection lands in `examples/rejections/` and joins the executable
  spec (`tests/test_frontend.py` REJECTIONS).
- Error messages are a deliverable (DESIGN §9): each names its guarantee and
  the fix — and is written for the model that will read it.
